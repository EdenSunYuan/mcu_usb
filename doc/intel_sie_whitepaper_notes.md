# 精读 Intel《Designing A Robust USB Serial Interface Engine》

> 这是一篇 1998 年 Intel 白皮书（`docs/intel_sie_design_paper.pdf`，共 9 页）。
> 它不教你"怎么写出一个 SIE"，而是告诉你"为什么你写出来的 SIE 会翻车、以及怎么不翻车"。
> 全文一句话：**SIE 很小（约 2500 门），但健壮性难题几乎全部来自多个异步时钟域 + 带内/带外信号的切换。**
>
> 本文是它的阅读笔记，重点讲两块：**DPLL 状态机**（我们已经完整实现）和**恢复时钟 dclk / 发送时钟 clk12s 的切换**（全文最绕也最关键的部分）。

---

## 0. 这篇文章在讲什么（一分钟版）

一个 USB 设备的硬件层次（原文 Fig.1）：

```
USB 收发器(Transceiver) → 串行接口引擎(SIE) → 缓冲区/接口逻辑 → 功能控制器
                            └── 本文主角 ──┘
```

SIE 是前端，处理 USB 规范第 8 章定义的、**到事务层为止**的协议。它要干的事有 8 类：

- 包识别、事务排序
- SOP/EOP/RESET/RESUME 信号的检测与产生
- 时钟/数据分离（CDR）
- NRZI 编解码 + 位填充/去填充
- CRC 生成与校验（Token 用 CRC5、Data 用 CRC16）
- PID 生成与校验/解码
- 串并 / 并串转换

这些功能加起来才 2500 门，很小。**难的不是功能，是"可靠"**。白皮书把翻车原因归成两大类，然后逐个击破：

1. **多时钟域**（首要原因，占全文一半篇幅）
2. **带内/带外信号处理**（SYNC/EOP 定界）、位填充、SETUP/ISO 特例、suspend/resume 等边角

## 1. 三大时钟域（全文的骨架）

SIE 要同时面对 **4 个时钟（dclk / ref_clk / clk12s / pclk），分属 3 个域**：

| 域 | 时钟 | 说明 |
|---|---|---|
| ① 接收时钟 | `dclk` | DPLL 从数据流里**恢复**出来的 12MHz，异步于本地 |
| ② 4× 时钟 + 发送时钟 | `ref_clk`(48MHz) + `clk12s` | 本地 48MHz，及它 ÷4 得到的发送时钟 |
| ③ backside 接口时钟 | `pclk`（我们）/ 任意 | 与 SIE 异步，字节宽接口 |

看懂这张表，全文就通了一半。后面每一节都在回答"这三个域之间怎么安全地传递信号"。

> **对应到我们的设计**：三个域齐了——`ref_clk`（= Intel 的 4× 48MHz）、`clk12m`（= Intel 的 1× 恢复/发送时钟，
> 接收时 = dclk、发送时 = clk12s，由 §3.4 的时钟 MUX 切出）、`pclk`（= Intel 的 backside）。
> **我们采用与 Intel 完全一致的架构：SIE 跑 1× clk12m 域**，CDC 边界就是 SIE↔backside（§6）。

## 2. DPLL 状态机（重点，我们已完整实现）

> 这一节对应白皮书 Fig.2。我们的 `src/phy/usb_rx_cdr.v` 就是它的 1:1 复刻，已通过 8 个用例 + 端到端回环验证。
> 下面按"为什么 → 怎么做 → 关键细节"展开。

### 2.1 为什么需要 DPLL：两个晶体天生异步

主机的 12MHz 和设备的 12MHz 来自**两颗不同的晶体**，各有 ±0.25% 的容差，所以**天生异步**。
接收端没有主机的时钟，只能从数据流里**逐位恢复**出"位时钟 + 数据位"——这就是 CDR（时钟数据恢复）。

这件事能做成，靠 USB 的两条规则兜底：

- **NRZI**：数据 0 = 电平翻转（产生跳变），数据 1 = 电平保持（无跳变）；
- **位填充**：连续 6 个 1 后强制插 0（保证跳变）。

于是线上**最长无跳变只有 6 bit**，自由运行的相位误差有界（6 × 0.25% × 4 ≈ 0.06 ref_clk），DPLL 才可能稳定锁住。**这是整个设计成立的前提。**

### 2.2 4× 过采样 + a/b 双沿（等效 8×）

`ref_clk = 48MHz = 12MHz × 4`，一个 bit 周期内有 4 个采样点，位边界分辨率 = 1/4 bit。
进一步对 `rxdp` 单端电平做**双沿采样**（J=1/K=0，J/K 恒互补，与差分线等价）：

```
rxdp ──┬──► [D] posedge ──► a   （48MHz 上升沿采样）
       └──► [D] negedge ──► b   （48MHz 下降沿采样）
```

一个 ref_clk 周期得 a、b 两个采样，一个 bit（4 ref_clk）内共 **8 个采样点 = 等效 8× 过采样**，
跳变检测分辨率达到 **1/8 bit**，能精确判断跳变落在哪个相位，从而决定频率往哪调。

### 2.3 状态编码：一个状态里同时嵌了"时钟"和"数据"

DPLL 用 **4-bit 状态、位编码**（不是 one-hot），两个 bit 直接携带要恢复的信息：

| 状态位 | 含义 |
|--------|------|
| `state[1]` | **恢复时钟**（0=低，1=高）——这就是 dclk 的原始来源 |
| `state[2]` | **NRZI 数据电平**（0=K，1=J）——这就是数据 |

状态机跑在 `ref_clk`（48MHz）上（`always @(posedge ref_clk)`），每拍读 `a`（本拍）和 `b`（上拍已锁存）。

### 2.4 16 态结构：锁定 + 左右环 + 绕行

```
                        ┌──────────── 数据 0（左环，电平 K）────────────┐
                        │   1 ──► 3 ──► 2 ──► 0 ──┐                  │
  C ──► D ──► 5 ──► 7 ──► 6 ──► 4 ──► 5          │（环尾判决态采样 a/b，│
  └ 锁存 ┘  └── 右环（数据 1，电平 J）──┘          │  有跳变切左、无跳变切右）│
                        └────────────────────────┴────────────────────┘
```

| 状态 | 恢复时钟 | 所属 | 说明 |
|------|---------|------|------|
| `1,3,2,0` | 外低内高 | **左环 · 数据 0** | 数据 0 的位周期；内两态(3,2)=clk 高，外两态(1,0)=clk 低 |
| `5,7,6,4` | 外低内高 | **右环 · 数据 1** | 数据 1 的位周期；内两态(7,6)=clk 高，外两态(5,4)=clk 低 |
| `C(12)` | — | 锁存 | 初始/未锁定态 |
| `D(13)` | — | 锁存 | 预锁态（检测到第 1 个边沿） |
| `F(15), B(11)` | — | 长 bit 绕行 | 位宽偏长时多耗一拍 |

完整跳转表（我们的实现，已逐项验证）：

| 当前 | 条件 | 下一 | 说明 |
|------|------|------|------|
| C | b≠0 | C | 等待首个边沿 |
| C | b=0 | D | 检测到数据 0 |
| D | b=0 | D | 等待第二个边沿 |
| D | b=1 | 5 | **锁定，进右环** |
| 1 | 无条件 | 3 | 左环前进 |
| 3 | a=0 | 2 | 左环前进 |
| 3 | a=1 | F | 长 bit 绕行 |
| 2 | b=0 | 0 | 左环前进 |
| 2 | b=1 | 5 | 短 bit/边沿，切右环 |
| 0 | b=0 | 1 | 左环回环 |
| 0 | b=1 | 5 | 边沿，切右环 |
| 5 | 无条件 | 7 | 右环前进 |
| 7 | a=1 | 6 | 右环前进 |
| 7 | a=0 | B | 长 bit 绕行 |
| 6 | b=1 | 4 | 右环前进 |
| 6 | b=0 | 1 | 边沿，切左环 |
| 4 | b=1 | 5 | 右环回环 |
| 4 | b=0 | 1 | 边沿，切左环 |
| F | 无条件 | 6 | 长 bit 绕行结束 |
| B | 无条件 | 2 | 长 bit 绕行结束 |
| （默认） | — | C | 兜底，回锁存态 |

### 2.5 频率自适应：短 bit / 长 bit

跳变出现的**相位**反映主机真实位率，状态机据此自适应：

| 主机位率 | 跳变出现相位 | 行为 | 恢复时钟 |
|----------|--------------|------|----------|
| 与标称同步 | 状态 0/4 | 正常切环 | 不变 |
| 偏快（短 bit） | 提前到 2/6 | 从 2/6 直接切环 | 低电平缩短 1 拍 |
| 偏慢（长 bit） | 推迟 | 从 3/7 经 F/B 绕行再切环 | 高电平加 1 拍 |

于是恢复时钟的**平均频率跟随主机实际位率**——这就是 DPLL 的"锁相"本质。

### 2.6 恢复时钟 dclk 的产生 + 两个"±"的辨析

- `state[1]` 是状态寄存器的原始位，切换瞬间组合路径可能有毛刺；
- 再经一级 `always @(posedge ref_clk)` FF 打一拍去毛刺 → 得到 glitch-free 的 **dclk**。

这里有个**容易混的两个"±"**，值得单独说清：

| | 数值 | 含义 |
|---|---|---|
| **稳态频率偏差** | ±0.25%（晶体容差） | dclk 的平均频率跟着主机的晶振走 |
| **瞬时周期抖动** | ±25% | dclk 单个 bit 周期被 4× 量化成 3/4/5 ref_clk |

白皮书那句 "At any bit, the derived clock period can be +/-25% of the nominal period"
指的是**后者**——单个 bit 的周期离散成 3 拍（短 bit，-25%）或 5 拍（长 bit，+25%）。
一句话：**dclk 不是干净的 12MHz 方波，而是一串 3/4/5 拍、逐个 bit 自适应主机的"时钟信号"。**

**关键推论（锁定门槛 vs 锁定后的自由运转）**：DPLL **至少要 2 个跳变才能锁定**（否则停在 C/D 态，出不了时钟）。所以**复位后、尚未锁定**时，空闲 / resume（连续 K）/ reset（SE0）都因边沿不足而没 dclk。

**但一旦锁定，dclk 就"自由运转"**：状态机只在两个环里循环（J→右环 5→7→6→4，K/SE0→左环 1→3→2→0），每环 4 态 = 1 bit，**空闲期（连续 J）照样输出干净的 12MHz 时钟**（周期恒 4 ref_clk）。我们的 CDR **没有任何"解锁回 C"的路径**（只有复位能回 C），所以锁定后 dclk 一直跑到复位——这带来一个下游后果：**clk12m（接收时 = dclk）在空闲期也在翻转**，SIE 的 bit→byte 逻辑照样每 bit 吐一个"数据 1"，SYNC 检测必须靠"空闲只出连续 1、无 0"来过滤（见 §4.2）。

**"吃位"的根因：空闲自由运行 → SYNC 重新对齐**。空闲期没有跳变，DPLL 只能跑标称 4 拍环——这个"自由 12MHz"**并不跟踪主机**（主机 ±0.25% 的晶振偏差在空闲期被"冻结"了），所以空闲越久，dclk 的相位就漂得离主机真实位边界越远。下一个包的 SYNC 一到，首跳变（J→K）就逼 DPLL 切环重新对齐，**对齐过程要"吃掉" SYNC 开头 1~2 个 0**。这就是下游 deserial 里"SYNC 吃位"（首包吃 2 位、后续包吃 1 位）的真正根因——不是 SYNC 本身短，而是**重新对齐要消耗几个边沿**。

## 3. 发送时钟 clk12s，以及"为什么 TX/RX 要切时钟"（重点）

### 3.1 clk12s 的产生

`clk12s = ref_clk(48MHz) ÷ 4`，**同步于本地 48MHz、始终在跑、永远精确 12MHz**。它和 DPLL 无关，
就是"我们作为发送方自己的位率"。发送时我们是速率主人，不需要从任何人那里恢复时钟。

### 3.2 dclk vs clk12s 的本质区别

| | dclk（接收时钟） | clk12s（发送时钟） |
|---|---|---|
| 来源 | DPLL 从数据流恢复 | 本地 48MHz ÷ 4 |
| 与本地 48MHz | 异步（跟主机晶振） | 同步（自己分频） |
| 周期 | 离散 3/4/5 ref_clk | 恒 4 ref_clk |
| 何时存在 | 锁定前无（需 2 边沿）；**锁定后始终在跑（含空闲期），直到复位** | 始终在跑 |
| 跟踪谁的时钟 | **主机的** | **我们自己的** |

### 3.3 为什么 TX/RX 必须切这两个时钟

三个理由叠加，缺一不可：

1. **USB 半双工**：同一组硬件（CRC、移位寄存器、位计数器、状态机）既要收又要发，**复用**。而收发不可能共用一个时钟源。

2. **收的时候必须用 dclk**：接收的数据是**主机**用它的时钟打出来的，相位由主机定。如果拿我们自己的 clk12s 去采样，两颗晶振 ±0.25% 的相对漂移（最坏 ±0.5%）会**逐 bit 累积**——一条包几百个 bit，采样点会漂出 bit 中心，直接错位。DPLL 的价值就是**每个数据边沿都重新同步一次**，让相位误差永远不累积超过 6 bit（位填充兜底）。

3. **发的时候必须用 clk12s**：发送时**我们**是主人，数据按我们的节奏往外打，自然用本地 clk12s（同步、相位确定）。注意——**此刻 dclk 并没有消失**：一旦锁定，DPLL 就一直自由运转输出 dclk（§2.6，只有复位才停），发送期也在跑。但发送时线上是我们自己发的信号、**没有主机的边沿可跟**，dclk 只能跑标称 4 ref_clk 周期、不再跟踪主机，把它拿去发送语义就错了。接收域（跟主机）与发送域（跟本地）必须各用各的时钟。

而每笔 USB 事务都**既有收相位又有发相位**（比如先收 token、再回 ACK/NAK handshake），
所以 SIE 状态机必须**在事务相位切换时，在两个时钟之间来回切**。

### 3.4 怎么切：无毛刺时钟 MUX（Fig.3）

两个时钟异步，**不能直接拿 MUX 一接**——切换瞬间 dclk 可能高、clk12s 可能低，会产生 runt pulse（毛刺脉冲），把 1× 域逻辑打乱。

白皮书给的是一个 **4 态状态机**：

```
     rcv=0 & dclk=0        clk12s=0        rcv=1 & clk12s=1        dclk=0
[0] ────────────────► [1] ─────────► [3] ─────────────────► [2] ──────────► [0]
 输出=dclk              输出=0         输出=clk12s               输出=0          (回到 0)
 (接收)                (过渡)         (发送)                   (过渡)
```

> 原图画成菱形：**0 在上、1 在左、2 在右、3 在下**，上面这条是把菱形拉直成环。图中还有一根 **reset 复位箭头从下方进入态 3**——上电先跑本地时钟 clk12s（此刻线上没数据、DPLL 锁不上、dclk 不存在），等收到包、`rcv=1` 才切去 dclk。四个边上的条件与状态编号都是从 Fig.3 原图直接识别的（正文第 4 页也明文写了"state 0 是 dclk、state 3 是 clk12s、其余态输出 0"）。

- **态 0**：输出 = dclk（接收中）
- **态 3**：输出 = clk12s（发送中）
- **态 1、2**：过渡态，输出恒 **0**

**核心手法**：过渡态（1、2）把输出**恒拉低**，拿"延长低电平"当两个时钟之间的缓冲——先切断旧时钟 → 停一拍低电平 → 再接新时钟。输出只在新时钟的上升沿处重新变高，永不产生毛刺。

**切换过程**（分两个方向，逐条）：

**方向① RX→TX（0→1→3）**，由 `rcv=0` 触发（收完 token，准备发 handshake）：

1. **0→1**：条件 `rcv=0 & dclk=0`。收到"转发送"命令后，**等 dclk 已为低**才切——在 dclk 低点断开，输出从"dclk 的低"过渡到"恒低"，无缝无毛刺。
2. **态 1 停留**：输出恒 0，低电平被拉长，等本地发送时钟就位。
3. **1→3**：条件 `clk12s=0`。等 clk12s 也变低，此时输出本就是 0、clk12s 也是 0，接上无缝；下一个 clk12s 上升沿就是 1× 域见到的第一个干净时钟沿。

**方向② TX→RX（3→2→0）**，由 `rcv=1` 触发（发完 handshake，切回收）：

1. **3→2**：条件 `rcv=1 & clk12s=1`。收到"转接收"命令后，**等 clk12s 已为高**才切——在高点断开 clk12s，输出从"clk12s 的高"跌到"恒低"，1× 域见到的最后一个时钟沿是干净的下降沿。
2. **态 2 停留**：输出恒 0。
3. **2→0**：条件 `dclk=0`。等 dclk 变低后接上，第一个上升沿干净。

**切断相位的"不对称"（诚实标注）**：

- 两个时钟**接入时都等低电平**（1→3 等 `clk12s=0`、2→0 等 `dclk=0`）——这是无毛刺的关键：从恒 0 接到 0，无缝。
- 但**切断时相位不对称**：0→1 在 **dclk 低点**切（输出 0→0，真正无缝）；3→2 在 **clk12s 高点**切（输出 1→0，一次干净的下降沿）。
- 为什么切 clk12s 不在低点？`rcv` 是 **1× 域里、由当前输出时钟打出来的**信号：发送期间它跟着 clk12s 走，发送收尾那一刻 `rcv` 变 1 时 clk12s 恰在高相位；接收期间跟着 dclk 走，转发送时 `rcv` 变 0 时 dclk 恰在低相位。所以这个不对称不是随意选的，是**协议状态机自身时序**决定的。只要守住两条——**断开后必进过渡态、接入前必等低电平**——无论在哪点断都不会出毛刺。

> ⚠️ 以上四个边条件（`rcv=0&dclk=0` / `clk12s=0` / `rcv=1&clk12s=1` / `dclk=0`）与状态编号，是**从 Fig.3 原图直接识别**得到的（正文第 4 页也明文写了"state 0 是 dclk、state 3 是 clk12s、其余态输出 0"），不是文字反推。

### 3.5 `rcv` 信号与 EOP 反射（详细）

`rcv` 信号和 EOP 反射是一个硬币的两面：EOP 反射之所以危险，恰恰因为它会**骗错 `rcv`**。下面拆开讲。

#### 3.5.1 `rcv` 是什么、起什么作用

`rcv`（receive）是 SIE 的**收发方向标志**，一个电平信号：

- `rcv=1`：**接收模式**——SIE 在听主机，用恢复时钟 dclk；
- `rcv=0`：**发送模式**——SIE 在驱动总线，用本地时钟 clk12s。

它的**首要作用**就是驱动 Fig.3 那个时钟 MUX：`rcv` 决定 `clk12m` 选 dclk 还是 clk12s。此外它还顺带门控收发器、
选择数据流向——一句话：**"当前这半拍，总线归谁"的总开关**。

#### 3.5.2 `rcv` 怎么产生

由 SIE 的**协议状态机**（事务相位控制器，跑 clk12m）产生，逻辑一句话：**"接下来这一拍，总线是主机→设备还是设备→主机"**——
`rcv=1` 表示我该听（主机→设备），`rcv=0` 表示我该说（设备→主机）。协议状态机根据 **token 类型 + 事务相位** 就能判定。

按事务相位翻转，两类事务的 `rcv` 序列：

| 事务 | 相位 | 动作 | `rcv` |
|------|------|------|-------|
| 任意 | 复位后 / 包间空闲 | 等主机下一个 token | 1（收） |
| IN | 收到 IN token | 准备发 DATA | 0（发） |
| IN | 发完 DATA + EOP（反射平息） | 等主机 ACK | 1（收） |
| IN | 收到 ACK | 等下一个 token | 1（收） |
| OUT / SETUP | 收到 OUT/SETUP token | 继续收 DATA | 1（收） |
| OUT / SETUP | 收到 DATA | **准备回握手（ACK/NAK/STALL）** | 0（发） |
| OUT / SETUP | 发完握手 + EOP（反射平息） | 等下一个 token | 1（收） |

一句话记忆：**主机说话我 `rcv=1`，我说话 `rcv=0`**；收到包后要不要"回话"（回握手 / 回 DATA）由 token 决定——
IN 回 DATA，OUT/SETUP 回握手。

它是**寄存器的干净输出**（不能是毛刺组合逻辑），因为 MUX 状态机对它的**电平**是立刻反应的。

#### 3.5.3 `rcv` 在哪个时钟域

- **产生**：1× 域（clk12m，协议状态机）；
- **消费**：4× 域（ref_clk，Fig.3 MUX 的状态机）；
- 所以 `rcv` 是一个 **1× → 4× 的跨域信号**。但如 §3.6 所述，clk12m = dclk 或 clk12s，边沿都 ref_clk 对齐，
  `rcv` 的边沿同样 ref_clk 对齐、且 4 拍才变一次，4× 采样它**无亚稳态**；
- 还有一个**环回依赖**：`rcv` → MUX → `clk12m` → 协议状态机 → `rcv`。之所以安全，是因为 `rcv` 只在事务相位边界
  变一次（每包一次，很慢），而 MUX 几个 ref_clk 拍就稳定了，反馈不会振荡。

> **时序约束（综合/STA）**：`rcv` 是**准静态**信号（每事务相位才变一次，非每周期翻转），严格说不是"多周期路径"
> （multicycle 是给每周期翻转、但允许 N 拍传播的数据路径用的）。但它跨 clk12m(1×)→ref_clk(4×)，工具默认按
> 1 个 ref_clk 周期（20.8ns）约束会报假违例，**需要放松**。三种放松手段：
> - **`set_false_path`**（最粗暴）：setup+hold 全关。对 rcv 而言"能用"——因为它边沿 ref_clk 对齐（无亚稳态）且准静态，
>   关掉检查不丢正确性。但代价是**吞掉未来改动**：一旦有人在 rcv 前加组合逻辑、或换掉 ref_clk 对齐的启动时钟，
>   它变成真 CDC bug 时工具不会报警；
> - **`set_multicycle_path`**（setup 4）：仅当 clk12m 能定义成干净的 ÷N 派生时钟才干净——clk12s（÷4）可以，
>   但 **dclk 周期 3/4/5 不固定**，工具没法定义成 ÷N 派生时钟，所以这条在 dclk 一侧走不通；
> - **`set_max_delay`**（推荐）：给准静态信号一个宽松上限（如 4~8 拍），既不死扣 1 拍，又保留"保险丝"——rcv 延迟
>   一旦异常爆炸，工具会报警而不是默默放行。
> 综上：rcv 用 `set_max_delay` 最稳，`set_false_path` 只在"纯参考设计、不集成、自知边沿对齐"时才用。真正的坑不是
> rcv 本身，而是 **dclk 这个寄存器派生时钟（周期不定）**——这是 Intel"跑恢复时钟"架构的 STA 痛点。
> 我们采用 Intel 同款架构，**dclk 周期 3/4/5 不固定的 STA 痛点照单全收**（这是选"SIE 跑 1× 域、bit 节奏天然同步"
> 所必须付出的代价，已在架构决策里接受，见 `02_clk_mux_design.md` §4.5）。

#### 3.5.4 EOP 反射是什么

**EOP**（End of Packet）是 USB 的"包结束"定界：发送端把 D+/D- 同时拉低成 **SE0**（单端零，两条线都 0）约
**2 bit**，再回到 **J（idle）约 1 bit**。SE0 是**带外**状态——有效数据只有 J/K，没有 SE0，所以它是"数据之外"的
边界标记。

**"反射"的来历**：USB 是**一条双向差分线**（D+/D- 两根线，主机和设备都挂在这两根线上）。设备发送时：

1. **自发直通（loopback）**：设备的差分接收器就接在同一对线上，发送时它**直接听到自己发的东西**；
2. **远端反射（echo）**：EOP 波形沿电缆传到对端（主机/集线器），对端**阻抗不匹配**（终端不完美）会把一部分信号
   **反射回来**，这段"幽灵回波"要经过往返延迟才回到设备接收器。

两者叠加：设备发完 EOP 后，**自己的接收器还会再次看到 SE0（甚至多次，含回波）**——这就是"EOP 反射"。

#### 3.5.5 危险：反射被当成"新包的开始"

问题出在**切回接收的时机**：

1. 设备发完包（含 EOP），要切回接收（`rcv` 0→1）等主机下一个包；
2. 若 `rcv` 翻 1 的瞬间，自己那笔 EOP（或其反射）还残留在线上，接收逻辑——此刻已进入"监听"态——看到残留的 SE0；
3. 新包本以 SYNC（`KJKJKJKK`，从 K 开始）开头，即"idle J → 离开 idle"的跳变；而残留的 SE0（或回波的振铃）
   **同样表现为"线离开 idle"**，能骗过"新包开始"的检测；
4. 于是 MUX 切回 dclk、SIE 进入接收态，**去解码一个其实是自己 EOP 鬼影的"假包"**——线上根本没有 SYNC，SIE 就在
   错误状态里等一个永远不来的 SYNC，直到主机真发下一个包（或超时）才恢复。

> 注意（修正前的说法）：危害不是"切回 dclk 没时钟、SIE 卡死"——dclk 一旦锁定就一直在跑（§2.6）。危害是
> **SIE 被自己的 EOP 鬼影骗进错误的接收态**。

#### 3.5.6 怎么防

1. **`rcv` 时机**：翻回 1 必须等 EOP 反射**平息**之后（Intel 白皮书原话："确保自发 EOP 的反射不被当作新包"）；
2. **`tx_active` 门控**：设备发送期间（及发送后一小段）**强制接收器/deserial 回 IDLE**，不吐字节，反射再花也进不来。
   在我们的设计里 `tx_active` 是**独立的发送标志**（发送期间拉高），专门门控 EOP 检测、门控 SIE RX 解码，防止自发
   EOP 反射被当成新包；`rcv` 则单独驱动时钟 MUX 的方向切换——两者各司其职，不合并。

### 3.6 这个切换状态机自己跑在哪个时钟域？（4× ref_clk 域，但转移条件是电平）

常被问错的一个点：Fig.3 那个 4 态状态机，**它自己跑在哪个时钟上？** 答案是——**跑在 4× ref_clk（48MHz）域**，是一个普通的 ref_clk 同步状态机。

看它的四个转移条件，全是**电平条件**（没有一句是"数到第几拍"）：

- `0→1`：`rcv=0 & dclk=0`　　`1→3`：`clk12s=0`
- `3→2`：`rcv=1 & clk12s=1`　　`2→0`：`dclk=0`

关键在这里：**dclk 和 clk12s 这两路时钟的"频率"虽然异步（一个跟主机晶振、一个跟本地），但它们的"边沿"都对齐到 ref_clk**：

1. `clk12s = ref_clk ÷ 4`，边沿天然落在 ref_clk 沿上；
2. `dclk` = DPLL 的 `state[1]` 经一级 `always @(posedge ref_clk)` FF 打一拍（§2.6），**边沿同样落在 ref_clk 沿上**——DPLL 已经用 4× 量化把主机的异步相位"掰"到了 ref_clk 的格子上，只是**周期**（3/4/5 拍）还在跟主机走。

所以两路时钟都是 ref_clk 域信号，状态机**可以直接在 `posedge ref_clk` 上采样它们的电平**，没有亚稳态。"等 `dclk=0`""等 `clk12s=0`"在实现上就是每个 ref_clk 拍采样一次电平、满足就跳。

**那"自定时"的说法从哪来？** 那是**逻辑视角**：它的转移是"等电平就位"（条件驱动），而不是"数固定拍数"（计数驱动）。这个"电平驱动"才是无毛刺的根源——它保证切断/接入都发生在所选时钟的安全相位（低点），与绝对频率无关。但**实现上它不需要电平敏感锁存、不需要异步电路**，就是一个 `always @(posedge ref_clk)` 的普通同步 FSM + 一个组合 MUX 输出。

> 唯一要留意的信号是 **`rcv`**：它由 SIE 的 1× 协议状态机（跑 clk12m）产生。但因为 clk12m = dclk 或 clk12s，边沿也都在 ref_clk 上，所以 rcv 的边沿同样 ref_clk 对齐、且稳定 4 拍才变一次，4× 采样它同样安全。§3.5.5 的 EOP 反射警告，防的是 rcv **电平错误**（被反射误触发），不是跨域亚稳态。
>
> 对应我们的设计：我们**照搬**这个时钟 MUX（SIE 跑 clk12m 1× 域，接收时 = dclk、发送时 = clk12s，靠 MUX 切出）。
> Intel 用 ref_clk 同步 MUX 省掉一个异步 CDC；我们同样接受这个方案——MUX 状态机跑 ref_clk，唯一跨域输入是 `rcv`
> （1× 域产出，但边沿 ref_clk 对齐，采样无亚稳态，§3.5.3）。详见 [02_clk_mux_design.md](02_clk_mux_design.md)。

## 4. SYNC 判断（包起始定界）

### 4.1 SYNC 是什么、为什么开头不可靠

每个包以一个 **SYNC** 开头，NRZI 线上标称 **`KJKJKJKK`**（= 数据位 `00000001`，7 个 0 + 1 个 1，LSb 先发）。作用：让接收端 DPLL 锁定 + 对齐位/字节边界，**SIE 从不把它当数据**。

但 SYNC **开头不可靠**，两个原因叠加：① hub turn-on 行为会扭曲最初几位；② DPLL 要几个边沿才能锁（§2.6），会"吃"掉开头 1~2 个 0。

### 4.2 怎么判断：只认尾巴

既然开头不可靠，Intel 的做法是**只用 SYNC 的后半段来检测**——反正定界只需要"信息从哪一位开始"（即 SYNC 的结尾）：

- 找**尾部特征**（NRZI 级上的 `…KK`，即最后一个"不翻转"的数据位），而不是要求完整 8 位 `KJKJKJKK`；
- 检测时**忽略包间 gap 和未锁定态**的输出（这两段 DPLL 吐的 bit 是垃圾，不能拿去匹配）。

### 4.3 时钟域：1× 域（切出来的 clk12m，接收中就是 dclk）

这是最容易被问错的一点，直接回答：**在 DPLL 提取出的数据流里检测，跑 1× 域**，用的正是 Fig.3 切出来的那个 clk12m（接收阶段它 = dclk）：

- **不是 4× 域（clk48m）**：技术上"在 DPLL 之前"也能检 SYNC，但那样检测到的"SYNC 尾部"还得再跟 DPLL 提取出的数据流做一次同步对齐，多一步、多一处竞态；Intel 原文明说 **easier and recommended** 的是在提取后的数据流里找。
- **不是 clk12s（发送时钟）**：接收阶段根本用不到发送时钟。

一句话：**SYNC 是"恢复数据流里的一个 pattern"，就该跟着恢复时钟 dclk（经 MUX 变 clk12m）和恢复数据一起走。**

### 4.4 产生什么关键信号

检测到 SYNC 尾部后，吐**一个"sync 命中 / 包开始"标志**，语义是：**下一个 bit 就是 PID[0]**。SIE 靠它三件事：① 启动 PID 解析（从此按字节对齐）；② 启动位填充计数器（填充从 PID 起算，SYNC 本身不填充）；③ 复位 bit/byte 计数器。

> 对应我们的设计：SYNC 检测在 **clk12m（1× 域）**，在 **NRZI 解码后的数据流**上找 `≥4 个连续 0 + 1 个 1`（这个 `1` 就是 SYNC 末位），命中后拉高 `rx_active`、下一 bit 当 PID[0]；SIE 数 `rx_valid` 脉冲（`rx_active`↑ 后第 1 个脉冲的字节）自判 PID，deserial 不标包首。我们检的是解码后的"7 个 0"，白皮书检的是解码前的"`…KK`"——同一个尾巴，两层抽象。

### 4.5 时钟 MUX 会不会影响 SYNC 检测？（关键，容易被忽视）

（回答一个常见疑问：clk12m 是 Fig.3 那个 MUX 选出来的，而 MUX 在态 1/2 会输出 0、复位后停在态 3 = clk12s——这些会不会影响最终用 clk12m 检 SYNC？）

结论先说：**MUX 的"职责"正是让 clk12m 在接收时 = dclk（不是 clk12s），这是对的；但它有两个"副作用窗口"，恰好和 DPLL 锁定问题叠在一起，导致 SYNC 只能检尾巴。真正吃位的是 DPLL，不是 MUX。**

**情形① 复位后（首包）**：复位把 MUX 打到**态 3（clk12s）**、DPLL 打到 C 态（dclk=0，锁不上）。此时无论 MUX 停在态 3（clk12s，**相位不对**）还是 `rcv=1` 后切到态 0（dclk=0，**根本没时钟**），clk12m 在 SYNC 开头都**不是"跟踪主机的恢复时钟"**。要等 SYNC 前 ~2 个跳变把 DPLL 锁上、dclk 开始翻转，clk12m 才变成真 dclk，检测器才开张 → **首包只能检尾巴（吃 ~2 位）**。

**情形② 发送切回收（后续包）**：只要 DPLL 之前锁过（设备先收过 token 才发 handshake），dclk 在发送期/空闲期**自由运转**（§2.6，无解锁路径），MUX 走 3→2→0 时 `dclk=0` 立即满足，切换在**包间空闲 gap**里就完成了。等下一个 SYNC 到时，clk12m 已经是 dclk，检测正常——但空闲期 dclk 相位漂了，SYNC 首跳变逼它**重新对齐**，仍吃 ~1 位（≈ 后续包吃 1 位）。

**要点**：MUX 的过渡态（1/2，输出恒 0）确实会让 clk12m 短暂"无时钟"，但这段空白**设计上就落在**要么"复位后 DPLL 还没锁"、要么"发送后的空闲 gap"这两个不含有效数据的窗口里，所以**不会破坏 SYNC 检测**。前提是 `rcv` 信号时序正确（§3.5.5 的 EOP 反射警告，就是防止 MUX 被误切）。

> 对应我们的设计：我们有这个时钟 MUX，"复位后 DPLL 未锁、要等 SYNC 前 2 个边沿锁定后才开始吐 bit"的问题同样存在，
> 所以我们的 SYNC 检测器（在 clk12m 1× 域）也只要求 `≥4 个 0`，不要求完整 7 个 0。

## 5. EOP 判断（包结束定界 + 带外信号）

### 5.1 EOP 是什么、为什么比 SYNC 难

EOP 是包结束定界：**SE0（带外，D+/D- 都拉低）约 2 bit-time，然后一个 J（带内）收尾**。难在三处：

1. **SE0 是带外信号**，与带内数据**异步**——主机到器件经过多级收发器，带内↔带外之间产生 skew；
2. 带内↔带外过渡会让差分接收器**多出边沿**，反过来扰动 DPLL 恢复的时钟；
3. 要**精确计时** SE0 宽度：USB 规范要求全速器件**接受 ≥82ns、拒绝 <40ns** 的 SE0。

### 5.2 时钟域：4× 域（clk48m = ref_clk）

和 SYNC 相反，EOP 检测在 **4× 域（clk48m）**，理由是**计时精度**：

- 82ns / 40ns 这种门限，1× 域（1 bit = 83.3ns）分辨率太粗，根本量不出来；
- 4× 域 1 拍 = 20.83ns，能分辨这个区间；判决点取 **3 拍 ≈ 62.5ns**（40~82ns 的中间值，见 §5.3）。

**EOP 检测在 4× 域、结果在 1× 域用**——所以它是又一个**跨域信号**，要走 Fig.4 那种竞态分析。

### 5.3 状态机（Fig.7）：5 个状态，3 拍 SE0 判 EOP

每个 4× 拍采样一次 `line_state`，判三个条件：

| 条件 | 含义 |
|---|---|
| `se0` | SE0（D+/D- 都低，带外） |
| `j` | J（带内空闲）；`j/eop` 里的 `eop` 是"此刻拉高 eop 输出"这个**动作**，不是输入条件 |
| 其他（`!(se0+j)`） | 既非 se0 也非 j 的一切——**严格说不一定等于 K**，就当作"除 se0/j 之外" |

Fig.7 共 **5 个状态**（5 个圈，从最上方顺时针）：`eop_idle` → `eop_se0_1` → `eop_se0_2` → `eop_se0_3` →
`eop_dead`（在最左侧）。`eop_se0_1/2/3` 就是**连续 3 个 48MHz 拍都采样到 `se0`**，即 SE0 持续约
**3×20.83ns ≈ 62.5ns**——正好取在规范"必拒 <40ns"与"必收 ≥82ns"的**中间值**上。

```
                 se0                 se0                 se0
[eop_idle] ──────────► [eop_se0_1] ──────────► [eop_se0_2] ──────────► [eop_se0_3]
    ▲                                                                       │
    │                                                                       │ se0（自环）
    └──────────────────── j（拉高 eop）──────────────────────────────────────┘

回退：se0_1 / se0_2 见"非 se0" → 直接回 eop_idle（SE0 太短，作废）
旁路：se0_3 见"其他(非se0非j)" → eop_dead；eop_dead 无条件回 eop_idle（其中 j 拉 eop）
```

**逐状态跳转表**：

| 当前态 | 条件 | 次态 | 动作 / 说明 |
|---|---|---|---|
| `eop_idle` | `se0` | `eop_se0_1` | 检测到 SE0，开始计时 |
| `eop_idle` | 非 `se0` | `eop_idle`（保持） | 没出现 SE0，一直待命 |
| `eop_se0_1` | `se0` | `eop_se0_2` | 第 2 拍 SE0 |
| `eop_se0_1` | 非 `se0` | `eop_idle` | SE0 太短（<2 拍），作废回 idle |
| `eop_se0_2` | `se0` | `eop_se0_3` | 第 3 拍 SE0（≈62.5ns） |
| `eop_se0_2` | 非 `se0` | `eop_idle` | SE0 太短（<3 拍），作废回 idle |
| `eop_se0_3` | `se0` | `eop_se0_3`（保持） | 长 SE0，不重复判 |
| `eop_se0_3` | `j` | `eop_idle` | J 收尾，**拉高 `eop`**（正常 EOP） |
| `eop_se0_3` | 其他（非 `se0` 非 `j`） | `eop_dead` | SE0 后非 J，走旁路 |
| `eop_dead` | `j` | `eop_idle` | **拉高 `eop`**（一个周期） |
| `eop_dead` | 非 `j` | `eop_idle` | 无条件回 idle（不拉 eop） |

**要点**：

- **回退一律回 `eop_idle`，不再绕 `eop_dead`**：`eop_se0_1`、`eop_se0_2` 中途见"非 se0"（SE0 太短）直接作废回 idle。
- **`eop_se0_3` 三条出口**：`se0` 自环（长 SE0）、`j` 回 idle 并拉 `eop`、`其他` 进 `eop_dead`。
- **`eop_dead` 是过渡态，不保持**：进入后**无条件回 `eop_idle`**（就待这一拍）；这一拍内采样到 `j` 就拉高 `eop` 一个周期，采样到"非 j"就默默回 idle。
- **`j/eop` 里的 `eop`**：是"此刻拉高 eop 输出"的动作；`eop` 是一个 48MHz 单拍脉冲。
- **`eop_dead` 的作用**：承接 `eop_se0_3` 见"其他"（SE0 后先出 K 的异常/过渡），在这一拍里等 J 补判 EOP，然后回 idle 收尾。

> 已按 Fig.7 原图确认：5 个状态名、3 拍 SE0（≈62.5ns）、`eop_se0_3` 的 `se0` 自环 / `j` 回 idle 拉 `eop` /
> "其他"进 `eop_dead`、`eop_se0_1/2` 的"非 se0"回 `eop_idle`、`eop_dead` 无条件回 `eop_idle`（`j` 时拉 `eop`）。
> 唯一保留为推断的是 **`eop` 是否在 `eop_se0_3` 的 `j` 出口也拉一次**（即正常/异常两处都拉），还是只在 `eop_dead` 拉；
> 若与原图不符请指正。

### 5.4 dead state 与 dribble bit

- **dead state（极左侧，`eop_dead`）**：EOP 检测和 J 检测来自**两个异步**通道，时间上对不齐（可能先看到 SE0 才登记到 J，或反过来）；`eop_dead` 就是吞掉这种"对不齐"的兜底态——`eop_se0_3` 见"其他"（非 se0 非 j）进 dead，dead **无条件回 `eop_idle`**（只待一拍）；这一拍采到 J 才拉 `eop`（补判 EOP）、采到非 J 就默默回 idle（不发假 EOP，交 §5.6 的 `rx_error` 兜底）。
- **dribble（残位）**：包尾最后一个数据位 → SE0 的带内→带外过渡处，差分接收器可能**多恢复 1 个伪 bit**。所以定界**不能依赖位计数**，要**靠 SE0→J 沿锚定**；且 dribble 可能跟在包尾 stuffed bit 之后，去填充要一并小心（见 §7）。

### 5.5 产生什么关键信号

4× 域吐出 **`eop`（包结束）信号，跨到 1× 域**，语义是"数据到此为止"。SIE 靠它：结束去填充、结束 CRC 校验、把包交接给上层。

> 对应我们的设计：**PHY 不全在 ref_clk 域**——EOP 检测（SE0 计时，需 4× 分辨率）留在 ref_clk（4×）域，产出 `eop`/`rx_error`；
> bit→byte 的 deserial 用 **clk_mux 之后的 clk12m**（接收阶段 = dclk，即 DPLL 恢复时钟先经 clk_mux 再驱动），
> 在 clk12m 1× 域做；deserial **不吐 `rx_last`**，包结束靠 `rx_active`↓（UTMI `RXActive` 模型）；
> SIE 若需"最后一字节"侧带供 CDC 跨 pclk，由 SIE 据 `rx_active`↓ 自行标记（§6.6）。
> §3.5.5 的 EOP 反射坑，正是这个 `eop` 信号反射/跨域时要防的。
>
> **`eop` 从 ref_clk 跨到 clk12m（plan B）**：`eop` 是 ref_clk 域的单拍脉冲（~20.8ns），直接 2-FF 跨到 clk12m 会被
> 采漏（clk12m 周期 83ns > 脉冲宽）。做法是**单向展宽**：ref_clk 域把 `eop` 展宽成 5~6 拍电平并自动清零，SIE 在
> clk12m 域用边沿检测吃掉这个宽脉冲。展宽不跨回（单向），无需握手。

### 5.6 落到 RTL 的三个信号：`rx_active` / `eop` / `rx_error` 解耦

Fig.7 的 `eop_dead` 不能只产出 `eop` 一个信号——`eop` 只在"SE0 后回到 J"时才拉，一旦 SE0 后持续非 J，
`eop` 就没了。若下游把"包结束"（`rx_active` 拉低）只挂在 `eop` 上，错误场景下 `rx_active` 会卡在 1，
SYNC 检测器（只在 `rx_active=0` 运行）停摆，后续包再也收不到——**接收通道死锁**。所以必须把三个信号拆开：

| 信号 | 语义 | 谁负责 |
|---|---|---|
| `rx_active` | 框住整包（这个包结束了没有） | **无论对错，包一结束就拉低** |
| `eop`（内部信号） | 正常包尾（SE0→J 收尾；**只在内部驱动 `rx_active`↓**，不对外吐 `rx_last`） | 只有 SE0→J 正常收尾才拉 |
| `rx_error` | 这个包是坏的 | 错误路径拉高，告诉 SIE 别按好包处理 |

关键点：**`rx_active` 的拉低从 `eop` 上解耦**——三条"包结束"路径都无条件拉低 `rx_active`，只在"是否报错/是否正常"上区分：

| 包结束路径 | `eop`（内部） | `rx_active` | `rx_error` | 语义 |
|---|---|---|---|---|
| `eop_se0_3` 见 `j`（正常 EOP） | 拉 | **拉低** | 保持 0 | SE0 后 J 收尾，绝大多数包 |
| `eop_dead` 见 `j` | 拉 | **拉低** | 保持 0 | K 毛刺 1 拍后 J 收尾 |
| `eop_dead` 见 非`j` | 不拉 | **拉低** | **拉高** | SE0 后持续非 J，判 EOP 错 |

这样 `rx_active` 在任意一条包结束路径上都一定拉低 → SYNC 恢复待命 → 下一包收得到，不死锁；`rx_error` 只在错误出口拉高 → 正常路径不受影响。这三条之外，还有两类"总线整个卡死"的终止（SE0 超长、数据段超长）见 §5.7。

**SIE 侧如何响应 `rx_error`**：USB 规范对"收到的 DATA 包有错"的标准处理是**沉默不应答**（让主机超时重传），而不是回 ACK：

| 场景 | 设备动作 |
|---|---|
| DATA 包 CRC 错 / EOP 错（`rx_error=1`） | **不应答**，主机超时重试 |
| DATA 包正常但设备暂时忙 | 回 NAK |
| DATA 包正常 | 回 ACK |

**落地提醒**：`rx_error` 要和 `rx_active` 拉低、以及包边界一起走 CDC——它是**侧带位**，跟 `rx_start`/`rx_last` 一样
随最后一字节的四相握手一起跨域（`usb_sie_cdc` 的 `rx_start/rx_last/rx_error` 三个侧带位，§6.6）。`rx_error` 若单独
一根线裸跨域，慢 pclk 会采漏，SIE 就看不到错误，等于白拉。

### 5.7 总线卡死的两类兜底：SE0 超长（Reset）与数据段超长（超时）

§5.6 的三条路径覆盖了"包正常或局部错误"的结束。还有两类**总线整个卡死**的极端情况，不靠 EOP 也能终结：

**（1）SE0 一直持续 —— 判总线复位（Reset），不是 EOP**

`eop_se0_3` 见 se0 是**自环**（长 SE0 不重复判 EOP），所以 SE0 若一直持续，EOP 状态机会永远停在 `eop_se0_3`，`rx_active` 也不动。但 SE0 长时间持续是 **Bus Reset**（总线复位），不是包尾。USB 1.1 有两个不同时长的"复位"：
- **主机/集线器发送复位**：拉 SE0 **≥10ms**（保证被设备可靠识别）；
- **设备检测复位**：只要连续看到 SE0 **≥2.5µs** 就应判复位（进入 Default 态）。

正确做法是**在 EOP 检测之外再放一个独立的 SE0 超时计数器**：
- 线状态为 SE0 时递增、非 SE0 时清零；
- 计数超过**设备侧检测阈值 2.5µs**（本设计采用 2.5µs，而非主机的 10ms）→ 拉高 `usb_reset`；
- `usb_reset` **复位整个设备**：EOP 状态机回 idle、`rx_active` 拉低、SIE/端点/寄存器全复位。

于是"SE0 超长"由 reset 兜底，"SE0 短 + J"由 EOP 兜底，两者互不干扰。注意 `usb_reset` 是**物理层事件**，要在 ref_clk 域的 SE0 超时计数里尽快产出去（复位不能走慢 CDC）。

**（2）数据段一直没 SE0 —— 判超时错误**

主机发数据发到一半卡住（总线停在 J 或 K 不动）时：DPLL 会对着恒定电平"恢复"出连续 bit（J→连续 1、K→连续 0，NRZI 不变），数据会**无限流进来**，但**永远没有 SE0 → 永远没有 EOP** → `rx_active` 卡死。

这是**协议层职责**，由 SIE 自己兜底，**不需要"告诉 PHY"**：在 `rx_active` 期间数 bit/字节，超过一个合法包的最大长度还没等到 SE0，就判超时错误 → **强制 `rx_active` 拉低 + `rx_error` 拉高**。

阈值依据：FS 最长合法包是 isoc（max payload 1023B），数据段 ≈ 1025 字节 × 8 bit ≈ 8200 bit，位填充 +1/6 后 ≈ 9.6kbit ≈ 0.8ms@12M；取一个安全余量（如 ≥1.5ms 或按字节计数 >1025B）即可，既覆盖合法 isoc 又远早于物理卡死。

**四类包终止汇总**：

| 终止类型 | 触发 | 动作 | 归属 |
|---|---|---|---|
| 正常 EOP | SE0（3 拍）→ J | `rx_active`↓（内部 `eop` 驱动，无 `rx_last`） | EOP 状态机 |
| EOP 错 | SE0（3 拍）→ 非 J | `rx_active`↓、`rx_error`↑ | EOP 状态机 |
| 总线复位 | SE0 ≥ reset 阈值 | `usb_reset`↑，全复位 | SE0 超时计数 |
| 数据超时 | `rx_active` 期间超长无 SE0 | `rx_active`↓、`rx_error`↑ | SIE bit/字节计数 |

## 6. 串并转换（bit→byte）与 backside 接口（byte 级 CDC）

这一节回答一个问题：**bit 变成 byte 之后，byte 要不要跨时钟域？怎么跨？** 结论——bit→byte 在**同一时钟域内**
完成（无 CDC），**CDC 发生在 byte 层面**：SIE 的 1× 恢复时钟域 ↔ backside 接口时钟域。

### 6.1 bit→byte（串并转换）：1× 域内，无 CDC

串并转换（白皮书功能清单里的 "Serial-Parallel Conversion"）发生在 1× 恢复时钟域（clk12m，接收时 = dclk）；
白皮书把它算在 SIE 内，**我们的设计 2026-09-20 起把它划给 PHY**（`src/phy/usb_rx_deserial.v`，切分与 UTMI 一致），下述时钟域结论两者完全相同：

- DPLL 每个 bit 恢复出 1 个**数据位**（`state[2]` 经 NRZI 解码）+ 1 个时钟 `dclk`（§2）；
- 数据位在 `dclk` 驱动下**逐位右移进 8-bit 移位寄存器**（去填充之后）；
- 每 8 拍（bit 计数器 0..7 计满）锁存出一个并行字节（LSb 先发），交给 PID/CRC/事务层。

因为"移位"和"锁存字节"用的是**同一个时钟 dclk**，**这里没有任何跨时钟域**——bit→byte 是纯同步逻辑。
白皮书也只在功能清单里列它，没单独讨论它的 CDC（因为本来就没有）。

```
数据位 ──► [SR: 8bit 移位寄存器] ──► 并行字节 [7:0]    （LSb 先发）
             ▲
           dclk（恢复时钟，每 bit 一拍）
             │
           bit 计数器 0..7 → 计满 8 锁存一字节 + 复位
```

波形（一个字节 = 8 bit）：

```
dclk   : ▁▔▁▔▁▔▁▔▁▔▁▔▁▔▁▔▁▔▁▔▁▔▁▔▁▔    （恢复时钟，每 bit 一拍）
bit    : b0 b1 b2 b3 b4 b5 b6 b7        （LSb 先发）
bit_cnt: 0  1  2  3  4  5  6  7  0 ...
byte   : ═══════════════[b7..b0]════════[下一字节]════   （计满 8 拍锁存一次）
```

### 6.2 真正的 CDC：byte 层面，SIE 1× 域 ↔ backside 域

两个时钟域：

| 侧 | 时钟域 | 时钟 | 性质 |
|---|---|---|---|
| SIE | 1× 恢复时钟域 | `clk12m`（接收时 = dclk） | 跟主机晶振，异步于本地 |
| backside | 接口时钟域 | 任意异步时钟（我们 = `pclk`） | 功能控制器/后端的时钟 |

白皮书原话："The SIE backside could be running on a different clock than the SIE; since the data transfer
interface is byte wide, standard four phase closed loop signaling with handshake signal synchronization can be
used." —— **字节宽 + 异步 → 四相闭环握手**，不上 FIFO。

### 6.3 握手设计（Fig.5 RX / Fig.6 TX）

**RX**（收到的字节 SIE → backside，Fig.5）：

```
 SIE（1× 域）                             backside（异步域）
   RX_DATA ───────────────────────────►    （握手期间字节保持稳定）
   READY   ────► [2-FF 同步] ──► READY_sync
                                     backside 看到 READY_sync 取走字节
   RD      ◄──── [2-FF 同步] ◄── RD
```

**TX**（要发的字节 backside → SIE，Fig.6）：

```
 SIE（1× 域）                             backside（异步域）
   TX_DATA ◄────────────────────────────    （握手期间字节保持稳定）
   READY   ────► [2-FF 同步] ──► READY_sync
                                     backside 看到 READY_sync 放上字节
   WR      ◄──── [2-FF 同步] ◄── WR
```

**四相闭环握手**：`READY`（SIE 说"我准备好了"）→ 对方回 `RD`/`WR`（"我取走 / 放上了"）→ SIE 撤 `READY` →
对方撤 `RD`/`WR`。每个握手信号都经 **2-FF 同步器**跨域，**数据字节在握手往返期间保持稳定**，所以采样到的
永远是稳定字节，不需要 FIFO。

### 6.4 握手波形（RX 为例）

```
RX_DATA    : ═══════[byte N]══════════════════════[byte N+1]══════════════
READY      : ______▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔______
READY_sync : ____________▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔____
RD         : ____________________________▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔____
             ▲ 字节稳定                     ▲ backside 取走
```

### 6.5 控制信号：用最快时钟（4×）同步

backside → SIE 的其他控制信号（非数据）也要同步，白皮书的做法是**用最快的时钟（4× ref_clk）同步**。
同步后落在 4× 域，若再给 1× 域用，还要做 §5 那种 1×↔4× 竞态分析（Fig.4）。

> 这**正好印证了我们的"无 FIFO CDC"决策**——Intel 自己就用"握手 + 字节稳定"（而非异步 FIFO）解决 SIE↔backside
> 的字节跨域。我们采用与 Intel 完全相同的架构（SIE 跑 clk12m 1× 域），CDC 边界**就是 SIE↔backside**，用的正是
> 白皮书这套四相闭环握手（已实现为 `usb_sie_cdc`，见 §6.6）。

### 6.6 落地：`usb_sie_cdc` 四相闭环握手模块（已实现 + 仿真验证）

白皮书 Fig.5/Fig.6 的四相握手，我们实现成独立模块 `src/sie/usb_sie_cdc.v`。它只做两件事：

1. **握手信号 2-FF 同步**（req 一个方向、ack 反方向，各一组 2 级 FF）；
2. **数据字节 + 侧带位直通**（发送端在握手期间保持稳定，接收端在使能沿采样）。

**四相协议本身由两端点实现**（SIE 主动发起、FIFO 响应），CDC 模块不插手协议状态机——这正是白皮书的模型：
READY/ACK 的四沿由 SIE 和 backside 各出一半，CDC 只提供"安全跨域"的同步器 + "字节稳定"的保证。

**端口信号**：

| 域 | 方向 | 信号 | 说明 |
|---|---|---|---|
| clk12m | SIE→CDC | `rx_data[7:0]` / `rx_start` / `rx_last` / `rx_error` / `rx_req` | SIE push 一个字节 + 侧带 |
| clk12m | CDC→SIE | `rx_ack` | FIFO 已取走 |
| clk12m | SIE→CDC | `tx_req` | SIE 请求一个字节 |
| clk12m | CDC→SIE | `tx_data[7:0]` / `tx_ack` | FIFO 供的字节（随 tx_ack 有效） |
| pclk | CDC→FIFO | `s_rx_data[7:0]` / `s_rx_start` / `s_rx_last` / `s_rx_error` / `s_rx_valid` | req 同步后 + 数据直通 |
| pclk | FIFO→CDC | `s_rx_ack` | 取走字节 |
| pclk | CDC→FIFO | `s_tx_req` | tx_req 同步后 |
| pclk | FIFO→CDC | `s_tx_data[7:0]` / `s_tx_ack` | 供字节 |

**内部逻辑**（每方向四个 2-FF 同步器 + 数据直通）：

- RX：`rx_req` 2-FF 同步 → `s_rx_valid`；`s_rx_ack` 2-FF 同步 → `rx_ack`；`rx_data/start/last/error` 直通 → `s_rx_*`。
- TX：`tx_req` 2-FF 同步 → `s_tx_req`；`s_tx_ack` 2-FF 同步 → `tx_ack`；`s_tx_data` 直通 → `tx_data`。

**为什么数据能"直通"**：四相协议要求发送端把字节在 req↑ 到 ack↓ 全程保持稳定，接收端在 req 同步后的使能沿采样，
所以数据线在任何可能被采样的时刻都是稳定的，无需再寄存、无需 FIFO。

> **验证**：`sim/cdc/` 下 13 相位扫描（pclk 相对 clk12m 偏移 0~60000ps）+ 自校验（RX 32 字节 + 侧带标志、
> TX 32 字节）全过。VCD 文本抽取确认了严格四相序列（req↑→ack↑→req↓→ack↓），并实测一个字节握手周期
> **750ns = 理论上限 P_max**（§6.7），印证了延迟推导。

### 6.7 三种 CDC 方案对比：四相(Level) / 两相(Toggle) / 单向通知

（回答"握手会不会影响吞吐"的核心，并给出每种方案的**最慢 pclk 要求**。）

**统一模型**：设 `Ts` = clk12m 周期 = **83.3ns**（SIE 侧）、`Tp` = pclk 周期（backside 侧）。
一次跨域 = 2-FF 同步器，延迟 **[1,2]·T(目的)**（第 1 级采样点 δ ∈ [0,T)，第 2 级再 +T）；
目的侧寄存应答再 **+1·T(目的)**。故"请求 + 应答"半回合 = **[2,3]·Tp + [2,3]·Ts**。
USB FS 字节速率 = 12M / 8 = **1.5 MB/s = 每字节 667ns**，握手吞吐必须 ≥ 该速率才不丢字节。

#### 6.7.1 四相握手（Level，全闭环）—— 当前 `usb_sie_cdc`

协议：`req↑`（数据就绪）→ `ack↑`（已取走）→ `req↓` → `ack↓`，**每字节 4 个边沿 = 2 个半回合**。

四相 = 两次往返，环路 8 段（4 次跨域 + 4 次端点反应）：

| 段 | 作用 | 延迟 |
|---|---|---|
| 1 | req↑ → req_sync↑ | [1,2]·Tp |
| 2 | FIFO 反应（ack↑） | 1·Tp |
| 3 | ack↑ → ack_sync↑ | [1,2]·Ts |
| 4 | SIE 反应（req↓） | 1·Ts |
| 5 | req↓ → req_sync↓ | [1,2]·Tp |
| 6 | FIFO 反应（ack↓） | 1·Tp |
| 7 | ack↓ → ack_sync↓ | [1,2]·Ts |
| 8 | SIE 反应（req↑） | 1·Ts |

每字节周期 **P₄ = 8 段之和 = [4,6]·Tp + [4,6]·Ts**：

| pclk | Tp | P_min(4Tp+4Ts) | P_max(6Tp+6Ts) | P_avg(5Tp+5Ts) | 对 667ns/字节 |
|---|---|---|---|---|---|
| 12MHz | 83.3ns | 667ns | 1000ns | 833ns | ❌ 平均就超 |
| 24MHz | 41.7ns | 500ns | 750ns | 625ns | ⚠️ 平均够、最坏靠缓冲 |
| 36MHz | 27.8ns | 444ns | 667ns | 556ns | ✅ 最坏刚好 |
| 48MHz | 20.8ns | 417ns | 625ns | 521ns | ✅ 从容 |

**最慢 pclk 要求（修正）**：
- **严格（最坏相位、零缓冲）**：`P_max ≤ 667` → 6Tp + 500 ≤ 667 → Tp ≤ 27.8ns → **pclk ≥ 36 MHz**。
- 平均（允许 FIFO 吸收相位抖动）：5Tp + 416.7 ≤ 667 → **pclk ≥ 20 MHz**。
- **当前设计 pclk=24MHz** 落在"平均够、最坏(750ns)靠 64B FIFO 缓冲"区间（实测 phase=20000 单字节握手 750ns 正是 P_max）。

> ⚠️ 之前把"最慢 pclk"说成 24MHz 是不严的：那是**带 64B FIFO 缓冲的可行值**，不是**零缓冲最坏相位**的下限。
> 零缓冲下四相（Level）的严格下限是 **36 MHz**。

#### 6.7.2 两相握手（Toggle，全闭环但只认沿）

协议：`req` **翻转**一次 = 新字节（电平不复位、靠沿触发）；`ack` **翻转**一次 = 已取走。
**每字节 2 个边沿 = 1 个半回合**，省去"回零"相，吞吐约翻倍。

实现要点：接收侧 2-FF 同步 + 1 级 FF 沿检测（`sync2 XOR prev`）；两端各维护一个 toggle 位且**初始必须一致**（失步则死锁）。

每字节周期 **P₂ = [2,3]·Tp + [2,3]·Ts**（只有 1 个半回合，无 ×2）。

**最慢 pclk 要求**：
- 严格（最坏、零缓冲）：`3Tp + 3Ts = 3Tp + 250 ≤ 667` → Tp ≤ 138.9ns → **pclk ≥ 7.2 MHz**。
- 平均：`2.5Tp + 208.3 ≤ 667` → **pclk ≥ 5.5 MHz**。

代价（相对四相）：① 两端维护并一致初始化 toggle 态（失步死锁）；② 失去"电平表示忙"语义；③ 多一级沿检测 FF。

#### 6.7.3 单向通知（data + req 翻转，无 ack）

发送端每来一个数据就**翻转一次 `req`**（电平不复位、靠沿触发），`data` 同步保持稳定；pclk 侧用 2-FF 同步 + 沿检测（`sync2 XOR prev`）**自己发现边沿**并锁存数据。**没有 ack**、不回传。

每字节延迟（仅前向、无回程，故**无 Ts 项**）：**P₃ = [2,3]·Tp**（2-FF 同步 [1,2]·Tp + 沿检测 +1·Tp）。

**最慢 pclk 要求（修正：此前"无下限"是错的）**：
- 发送端每 667ns 翻转一次 `req`（1.5 MHz 翻转率）；pclk 侧须在**下次翻转前**用 3 拍（`sync1→sync2→prev`）完成沿检测并锁存数据，即 req 每个电平（667ns）内要有 ≥3 个 pclk 沿。
- 严格（最坏、不丢）：`3Tp ≤ 667` → Tp ≤ 222ns → **pclk ≥ 4.5 MHz**。
- 平均：`2.5Tp ≤ 667` → **pclk ≥ 3.75 MHz**。
- 一般式：`req` 每 `T_data` 翻转一次，需 `3·Tp ≤ T_data`（锁存发生在翻转后 [2,3]·Tp，必须赶在下个翻转改数据前）；松界（Nyquist）为 pclk ≥ 2×翻转率（FS 时 ≥3 MHz）。

**适用**：无确认、无流控，丢一个沿就丢一字节 → **只能用于可容忍丢失、或天然低速的事件/状态**（`in_acked`、中断、`data_toggle` 状态），**不能用于字节流数据通路**（字节流用四相/两相）。

#### 6.7.4 三方案对比总表

| 方案 | 每字节边沿 | 每字节延迟 | 最慢 pclk（零缓冲最坏） | 平均下限 | 反馈 | 复杂度 | 适用 |
|---|---|---|---|---|---|---|---|
| 四相 Level | 4 | [4,6]Tp+[4,6]Ts | **≥36 MHz** | ≥20 MHz | 全闭环（电平） | 低 | 当前 `usb_sie_cdc` 字节流 |
| 两相 Toggle | 2 | [2,3]Tp+[2,3]Ts | **≥7.2 MHz** | ≥5.5 MHz | 全闭环（沿） | 中 | 更快字节流 |
| 单向通知 | 1 | [2,3]Tp | **≥4.5 MHz** | ≥3.75 MHz | 无 | 低 | 可丢/低速事件 |

#### 6.7.5 结论

1. **当前 `usb_sie_cdc` 用四相 Level**：零缓冲严格最慢 pclk = **36 MHz**；配 64B FIFO 后 pclk=24MHz 也够（平均 625ns < 667ns，最坏 750ns 靠 FIFO 吸收）。**修正点**：之前"最慢 pclk = 24MHz"是带缓冲的可行值，非零缓冲下限。
2. 若想**降 pclk 或提吞吐**：换两相 Toggle，最慢 pclk 降到 **~7.2 MHz**、吞吐翻倍，代价是 toggle 状态维护 + 沿检测。
3. **单向通知（data+req 翻转、pclk 检沿、无 ack）**：最慢 pclk ≈ **4.5 MHz**（3·Tp ≤ 667，无回程 Ts 项），三者最快但**无确认**，只用于可丢/低速事件（`in_acked`、中断等），不搬字节流。
4. 决策：字节流继续走四相（简单、鲁棒、已验证）；未来 pclk 受限或吞吐不足再切两相。
5. **为什么数据通路不用单向通知**：TX（FIFO→SIE）是"拉"——SIE 是发送时序主人、必须主动要字节，天然需要请求+响应，单向通知表达不了"给下一个字节"，故 TX 用不了；RX（SIE→FIFO）虽是"推"、单向理论上可行，但会丢掉每字节"已收"确认与流控，FIFO 一满就静默丢字节。所以单向只留给 `in_acked`/中断等单比特事件，字节流仍走四相（或未来两相）。

### 6.8 控制信号 / data toggle / 传输结束反馈（SIE↔端点的接口层）

四相握手搬的是**数据字节**。除此之外 SIE 还需要和端点层交换三类**控制/事件**信号（都是慢信号，2-FF 同步即可）：

**（1）应答控制（pclk → SIE）**：每个端点方向只给两根准静态标志 `ep_stall`、`ep_nak`，两者都无效 = 正常（ACK/发 DATA），
不需要显式 ack。SIE 在**解析完 token 的 PID+ENDP 之后**（token 第 3 字节、SYNC 起 ~24 bit 后）采样它们——此时它们
必已稳定（只在 CPU 读写 FIFO / 事务完成 / SETUP 时才变）。

| ep_stall | ep_nak | SIE 动作 |
|---|---|---|
| 0 | 0 | 正常（ACK / 发 DATA） |
| 0 | 1 | NAK（临时无数据 / FIFO 满） |
| 1 | x | STALL（持续 halt，SETUP 才清） |

**（2）data toggle（双向）**：SIE 拥有 toggle（每端点 1 bit，收到 ACK 才翻、NAK 不翻）——只有 SIE 看得到主机
ACK/NAK。SIE→CPU 输出 `data_toggle`（读状态），CPU→SIE 给 `toggle_set`+`toggle_val`（写初值）。规则：SETUP 恒
DATA0，SETUP 之后数据/状态阶段用 DATA1（SETUP 后把 toggle 初始化成 1）。

**（3）传输结束反馈（SIE → pclk，事件）**：

| 事件 | 触发 | pclk 动作 | 跨域方式 |
|---|---|---|---|
| `rx_pkt_done` | OUT/SETUP 收包完整 + CRC 好 | 置 data_valid=1 + 拉中断 | 挂在 `rx_last` 侧带（随四相握手） |
| `in_acked` | IN DATA 被主机 ACK | 清 data_valid、FIFO 弹栈、翻 toggle | 独立脉冲，需脉冲 CDC |

`rx_last` + `rx_error=0` 本身就是"收包完成"，无需额外脉冲；只有 `in_acked` 是独立事件（脉冲 CDC：toggle 同步 + 边沿
检测，或直接 2-FF + 单拍检测）。

### 6.9 RX / TX 全情形 + 相关信号（枚举）

**RX（OUT/SETUP 方向，设备收）**：

| # | 情形 | SIE 动作 | 需 pclk→SIE | 触发 SIE→pclk |
|---|---|---|---|---|
| R1 | 收 SETUP | 必 ACK，清 STALL，toggle→DATA1 | 无（强制 ACK） | `setup_recv`（清 stall/reset toggle） |
| R2 | 收 OUT，有空间 | ACK + 收 DATA | stall=0, nak=0 | `rx_pkt_done`→data_valid=1+中断 |
| R3 | 收 OUT，FIFO 满 | NAK | nak=1 | — |
| R4 | 收 OUT，halt | STALL | stall=1 | — |
| R5 | 收 DATA，CRC 错 | 静默不应答 | 无 | 无（不置 data_valid） |
| R6 | 收 DATA，toggle 错 | ACK 但丢弃 | 无 | 无 |
| R7 | 收 SOF | 更新帧号 | 无 | 帧号（可选） |

**TX（IN 方向，设备发）**：

| # | 情形 | SIE 动作 | 需 pclk→SIE | 触发 SIE→pclk |
|---|---|---|---|---|
| T1 | 收 IN，有数据 | 发 DATA(toggle) | stall=0, nak=0 | — |
| T2 | 收 IN，无数据 | NAK | nak=1 | — |
| T3 | 收 IN，halt | STALL | stall=1 | — |
| T4 | DATA 后收 ACK | 完成，翻 toggle | — | `in_acked`→清 data_valid、弹栈 |
| T5 | DATA 后收 NAK | 保留数据，重发 | — | 无（不翻 toggle、不清） |
| T6 | DATA 后无响应 | 超时，重发 | — | 无 |

## 7. 其他设计细节（速览）

- **位填充**：填充/去填充时**让状态机和数据通路 hold 一拍**；**EOP 附近的去填充**要小心（dribble 可能跟在 stuffed bit 后）。
- **ISO 只有两相**（无握手）；**SETUP 等同 OUT 但不能 NAK/STALL**；控制传输各阶段的 **data toggle 初值**有专门要求。
- **低速**：极性反、reset 的 SE0 按时间不按 bit、keep-alive（裸 EOP）。——**我们 FS-only，整段跳过**。
- **reset 检测**：SE0 计时器复位会输出"一串 reset 脉冲"，器件要能正确处理。
- **remote wakeup**：要能脱离时钟计时；主机唤醒事件相对 remote wakeup 随时可能发生。
- **suspend**：挂起时要维持地址、接口设置等状态。

## 8. 结论 + 给我们的启示

白皮书结论：**异步时钟域**是 SIE 健壮性的头号敌人；用 DPLL + 可靠的时钟切换 + 仔细的时序路径分析能搞定；带内↔带外切换需要 dead state 和 dribble bit。

对照我们的架构，**我们最终采用了与 Intel 完全一致的架构：SIE 跑 1× clk12m 域**（接收时 = dclk、发送时 = clk12s，
靠 Fig.3 时钟 MUX 切出），CDC 边界就是 SIE↔backside（四相闭环握手）：

```
Intel / 我们:
  DPLL(4× ref_clk) ──dclk(恢复 1×)──┐
                                      ├─[时钟 MUX]─ clk12m ─ SIE ──四相握手── 端点 FIFO(pclk)
  ÷4(本地 48MHz) ──clk12s(发送 1×)──┘
  EOP/SE0 检测(ref_clk 4×) ──eop/rx_error──► SIE（跨域，plan B 展宽）
```

- Intel 的"1×↔4× 竞争冒险" + "时钟 MUX"，我们**照单全收**（MUX 跑 ref_clk、rcv 边沿 ref_clk 对齐无亚稳态）；
- Intel 的 TX 时钟 clk12s = ref_clk ÷ 4，我们同样用 ÷4 计数器产生；
- Intel 的"EOP 反射误切回 dclk"警告，我们同样用 `rcv`（合并了 `tx_active`）做门控 + EOP 反射防护；
- Intel 的"backside 四相闭环握手"，我们实现为 `usb_sie_cdc`（§6.6，已仿真验证）。

**已覆盖（截至 2026-08-21）**：
- DPLL（`src/phy/usb_rx_cdr.v`，8 用例 + 回环验证）；
- 时钟 MUX（`02_clk_mux_design.md` 已设计，rcv 驱动）；
- SYNC/EOP 检测（EOP 在 ref_clk 4× 域 + plan B 展宽；SYNC 在 clk12m 1× 域）；
- **四相握手 CDC（`src/sie/usb_sie_cdc.v`，13 相位扫描 + 自校验通过，实测握手周期 750ns = 理论 P_max）**。
