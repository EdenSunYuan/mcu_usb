## 1. 模块介绍

`usb_bus_state` 是 USB 1.1 数字收发器（PHY）的第五个子模块，与 `usb_rx_deserial` 并列。它只干一件事：盯着两路线电平，把总线上的宏观状态判出来报给 SIE。

输出四个脉冲：`connect_evt`、`usb_bus_rst`、`suspend_evt`、`resume_evt`，
外加一路电平 `bus_suspended`（挂起态，给 `usb_tx_serial` 的唤醒旁路，见下文）。

几个边界先交代：

- 时钟：判据在 `ref_clk`(48MHz) 域算，四个输出脉冲在 `clk12m` 域组合直出（见下文）。
- 只认线电平：输入是 `usb_rx_deserial` 采好的单端电平 `line_s[1:0]`，分 J/K/SE0 三态（见下文），不解析位，也不解析字节。
- 结构很小：一条计数器、两个标志位、两个翻转位。线一变就清计数器，计到某个值时看线状态和标志位决定出哪个事件（见下文）。
- 往上是 SIE（四个脉冲），往下只接两根信号：`usb_rx_deserial` 的采样电平和 `usb_tx_serial` 的 `tx_en`。`rcv` 由 SIE 产生，寄存器堆也不在本模块里。
- 唤醒的两条路径都从这里过。主机驱的 K 判成 `resume_evt`；设备自己驱的那段 K 靠 `tx_en` 挡在判据之外，不报事件，等主机接管驱 K 时照常出 `resume_evt`（见下文）。
- 软复位与总线复位在外面并成 `usb_rst` 一根进来，本模块只吃它，不产生也不分发（见下文）。

### 1.1 四项职责与规范门限

| 职责 | 物理现象 | 门限 | 出处 |
|---|---|---|---|
| 连接 | 线保持 J | ≥2.5µs | USB 1.1 规范·连接检测 |
| 总线复位 | 线保持 SE0 | ≥2.5µs | USB 1.1 规范·复位检测 TDETRST |
| 总线挂起 | 线保持空闲（J）无活动 | >3ms | USB 1.1 规范·挂起检测 |
| 被动唤醒（主机 resume） | 挂起中主机驱 K | ≥2.5µs | 规范·挂起检测；指南·主机 Resume 设计 |

主动唤醒（远程唤醒）不出现在这张表里，因为它没有自己的门限：设备驱的那段 K 被 `tx_en` 挡掉，主机接管后驱的 K 走的是表里最后一行那条判据（见下文）。发 K 前要满足的三个前置条件由软件和 SIE 把关，其中 5ms 的 TWTRSM 是软件写 `wkup_req` 之前该自己计的时间。

表里三个 2.5µs 门限数值一样，判据是线状态不同（J / SE0 / K），所以实现上共用一条计到 120 的计数器。

### 1.2 层次位置

```
   DP/DN ──┬──► usb_rx_cdr ──dclk──► usb_clk_mux ──clk12m──┬──► usb_rx_deserial ──► rx_data/…
           │                                               │                    │
           │                                               │      line_s ───────┘
           │                                               ▼
           │                                        usb_bus_state ──┐
           │                                               ▲         │
           │                                               │         │
           │                                      tx_en ───┤         │
           │                                               │         │
           │                                        usb_tx_serial ◄──┘
           └───────────────────────────────────────────────┘
                                                       四个 clk12m 脉冲 ──► usb_sie
```

`usb_bus_state` 与 `usb_rx_deserial` 是平级关系：判据都跑 `ref_clk`，同一次 SE0 两边数出的拍数一样（见下文），`rx_deserial` 拿它判包尾 EOP，本模块拿它判复位与挂起，区别只在门限时长。线电平不采两遍：`line_s` 由 `usb_rx_deserial` 采一次送过来，两个模块在 PHY 顶层挨着实例化，端口直连，本模块只再打一拍存 `line_s_dly` 用来判线变化。

### 1.3 为什么判据在 `ref_clk`，输出在 `clk12m`

判据只能跑 `ref_clk`，三个理由：

1. `clk12m` 从哪来是由总线状态决定的。它是 `usb_clk_mux` 在 `dclk` 与 `clk12s` 之间选出来的，DPLL 未锁时 `dclk` 还停着。而挂起判定的前提恰恰是总线上没有活动，判据不能建在由总线边沿派生的时钟上。
2. 4× 的精度刚好够。2.5µs = 120 拍、3ms = 144000 拍，都在 18 bit 以内。
3. `pclk`(24MHz) 反而不顺手。2.5µs = 60 个 `pclk`，数得过来，但复位出口、K 的边沿识别这些微秒级判据都要多付一层同步延迟，而这几个事件的消费者本来就都在 `clk12m` 域。

输出落 `clk12m` 的原因更简单：消费者是 SIE 与 PHY 内的 `usb_rx_deserial`、CDR，都在这个域，同域交付省掉下游各自同步的手续。跨域这一步在本模块内部一次性做完（见下文）。

## 2. 模块设计理论和原理及方法

### 2.1 设计动机：为什么不放 SIE 里

USB 设备要响应四种总线宏观事件，物理现象都是同一类事：某条线电平保持了多久。

- 连接：设备把 D+ 拉高（1.5kΩ 上拉）后，主机看到 J 就认为设备在位。设备侧的判据是 J 持续 ≥2.5µs，比这短的一律按数据位算。
- 复位：主机把两线都拉低 ≥10ms（TDETRST 只要求设备在 2.5µs 内识别）。设备得靠 SE0 的持续时间区分三件事：包尾 EOP 的 SE0（≈160ns）、总线复位（≥2.5µs）、挂起之后的长 SE0（主机掉电或者线被拔了）。
- 挂起：总线空闲（J）超过 3ms。
- 唤醒：分两半。被动唤醒是主机驱 K；主动唤醒是设备自己驱 K 1~15ms，前置条件由软件把关。

为什么不放 SIE 里做？SIE 跑 `clk12m`，而这个时钟的存活性不由 SIE 决定（见上文）；SIE 的协议 FSM 已经在管包级和事务级时序，再塞毫秒级计数器进去，状态空间要翻一倍；挂起时 SIE 恰恰该停下来，没法指望它继续计时。所以单独成模块，跑 `ref_clk`。

### 2.2 线状态分类与 `driving` 门控

单端两线一共四种组合，合法的只有三种：

| `line_s` | 名称 | 含义 | 全速下出现场合 |
|---|---|---|---|
| `2'b10` | J | D+ 高、D- 低 | 空闲（idle） |
| `2'b01` | K | 反向 | 数据位、resume 信令 |
| `2'b00` | SE0 | 两线同低 | EOP（≈160ns）、复位（≥2.5µs） |
| `2'b11` | SE1 | 非法 | 只在电平交叉瞬间（≤14ns） |

SE1 不做判据，只认 J、K、SE0。规范里 SE1 是「不允许被解释成任何信令」的交叉瞬间，给它开一条「持续超限就报错」的通路，只会多出一批够不着的分支；真要是 SE1 一直赖着不走，那说明 PHY 坏了，另外三态停摆一样看得出来。

表里最后一列有个例外要说清楚：电缆没插时，`D-` 那侧没有主机的 15kΩ 下拉，两线可能长时间停在 SE1 或 SE0，不是 14ns 的瞬间。所以「SE0 持续 2.5µs 就是复位」这条不能无条件成立，得先确认连接过（`connected`，见下文）。

**采样口径**：线电平在 `usb_rx_deserial` 里于 `ref_clk` 域打一拍存进 `line_s[1:0]`，本模块直接吃这一份，另打一拍存 `line_s_dly` 用来判线变化。共用一份的好处是 EOP 判据和复位判据天然拿同一把尺子比，不必去解释两个采样器之间的先后。两线来自模拟比较器，单拍采样就够，后面的门限都是 120 拍量级，21ns 的采样偏差进去无所谓。`line_s` 不吃 `usb_rst`：它就是总线本身，复位要是动了它，复位撤掉那一拍反而会造出一次假线变化。

**`driving` 门控**：

```
driving = tx_en;      // 组合直连，不打拍、不同步
```

这里取的是 `tx_en`（`usb_tx_serial` 的驱动器使能输出），不是 SIE 的 `tx_active`。`tx_active` 只是发送请求，`tx_en` 才是「驱动器真在驱」：起包时 `tx_en` 比 `tx_active` 晚一拍（那一拍线上还是 J），中止时它也晚一拍落，两种情况都不会在「我们没驱」的时候把计数器清掉。包尾的 EOP 段 `tx_en` 仍是 1（要到帧机回 `S_IDLE` 才清），自己发的 EOP SE0 天然落在门控窗口里。`tx_en` 置起时线上跑的是我们自己的 NRZI 和 EOP，也包括远程唤醒那 1~15ms 的 K。这段时间计数器清 0，四个判据被 `~driving` 全部挡掉（见下文）。

`tx_en` 在 `clk12m` 域，但这里既不同步也不打拍。理由是 `clk12m` 的两个来源都在 `ref_clk` 域寄存产生：`dclk` 是 `usb_rx_cdr.v` 里 `ref_clk` 触发器的直出，`clk12s` 是 `ref_clk` 分频。`clk12m` 的每个沿都是某个 `ref_clk` 沿的后果，`tx_en` 作为 `clk12m` 域触发器，变化必然落在 `ref_clk` 沿上，`ref_clk` 域的组合逻辑读它不会亚稳。这与 PHY↔SIE「同步派生时钟交接、无异步 CDC」的口径一致。

直连要付的代价是 `tx_en` 沿相对 `clk12m` 沿的 Tco 偏差：`clk12m` 边沿之后 `tx_en` 才更新，同一拍 `ref_clk` 组合逻辑读到旧值，下一拍读到新值。对清零和判据都没影响：门限是 120 拍量级，差 1 拍（20.83ns）远在裕度内，而 `tx_en` 全程为 1 的那 1~15ms 里 `driving` 恒为 1。

### 2.3 一条计数器、四个判据

`ref_clk` = 48MHz，1 拍 = 20.83ns。任何线变化都清计数器，门限命中那一拍拿线状态和标志位比一遍。
下表把「两个门限 × 四种线状态 × 两个标志位」的组合列全，`driving`=0：

| `cnt` | 线 | `conn`/`susp` | 判据 | 事件 | 标志位动作 |
|---|---|---|---|---|---|
| 120 | J | 0 / 0 | `con_cond` | `connect_evt` | `connected`→1 |
| 120 | J | 1 / 0 | — | 无 | — |
| 120 | J | 1 / 1 | — | 无 | — |
| 120 | K | 0 / 0 | — | 无 | — |
| 120 | K | 1 / 0 | — | 无 | — |
| 120 | K | 1 / 1 | `rsm_cond` | `resume_evt` | `suspended`→0 |
| 120 | SE0 | 0 / 0 | — | 无 | — |
| 120 | SE0 | 1 / 0 | `rst_cond` | `usb_bus_rst` | — |
| 120 | SE0 | 1 / 1 | `rst_cond` | `usb_bus_rst` | `suspended`→0 |
| 120 | SE1 | 0 / 0 | — | 无 | — |
| 120 | SE1 | 1 / 0 | — | 无 | — |
| 120 | SE1 | 1 / 1 | — | 无 | — |
| 144000 | J | 0 / 0 | — | 无 | — |
| 144000 | J | 1 / 0 | `sus_cond` | `suspend_evt` | `suspended`→1 |
| 144000 | J | 1 / 1 | — | 无 | — |

```verilog
// 线状态分类
assign line_j   = (line_s == 2'b10);
assign line_k   = (line_s == 2'b01);
assign line_se0 = (line_s == 2'b00);

// 门限命中：计数到位，且本拍线没变
assign cnt_2p5u = (cnt == CNT_2P5U) & (~line_chg);
assign cnt_3ms  = (cnt == CNT_3MS)  & (~line_chg);

// 四个判据 = 门限 + 线状态 + 标志位
assign con_cond = cnt_2p5u & line_j   & (~driving) & (~connected);
assign sus_cond = cnt_3ms  & line_j   & (~driving) & connected & (~suspended);
assign rst_cond = cnt_2p5u & line_se0 & (~driving) & connected;
assign rsm_cond = cnt_2p5u & line_k   & (~driving) & suspended;

// 计数器：线一变就清零，我们自己在驱时也清零；上界随线状态
assign cnt_clr = driving | line_chg;
```

几条性质按重要性排：

- 线变化清零本身就等于在测「保持时长」。计到 120 而中间没人清它，说明线 120 拍没变过，也就是保持了 2.5µs。三个 2.5µs 门限因此不用三条计数器，看线状态就分开了。
- 计数上界随线状态走，到顶就停：J 态 144001，其余态 121。每个线状态只留它可能用到的那个门限，长 SE0（比如复位挂着）时高位计数器不再翻转，计数器因此只要 18 bit。
- 上界取「门限 + 1」而不是门限本身，是给计数器留一个不等于门限的落脚点，`cnt == 门限` 才只在门限那一拍成立。`rst_cond` / `rsm_cond` 拿去翻 `rst_tgl` / `rsm_tgl`，翻转位的规矩是「一次事件翻一次」，`clk12m` 侧才能用新旧不同换出一个脉冲。计数器要是停在门限上，`cnt == 门限` 就一直成立、判据成了电平，翻转位在这段电平里每拍都翻；48MHz 的翻转送进 12MHz 的采样链，两次采样之间它翻两次又翻回来，采样到的值看着没变，事件可能一个都不出。多出来的这一拍由下文那段实测给出。
- 门限命中要带 `~line_chg`。`line_s` 刚更新那一拍，`cnt` 还是旧值而线已经是新水平，此时若 `cnt` 恰好等于门限，判据就会拿「旧计数 + 新线状态」去比，一段 2.5µs 的 K 会被误算成主机 resume。加上它之后，判据的含义才是严格的「当前这个线水平已经保持 120 / 144000 拍」。
- `driving` 期间也要清零，否则自己驱的那 1~15ms 唤醒 K 会被当成主机 resume（见下文）。四个判据里再各写一次 `~driving` 是第二重保险：清零和判据求值在同一拍上有一个竞争窗口。
- SE1 不参与任何判据，但它也是一次线变化，照样清计数器，等于把交叉瞬间当活动看待。

四条判据之间互斥：120 和 144000 差着 143880 拍，线上的 J/K/SE0 又只能取一个值。

SOF 不会把设备误判成挂起。主机每 1ms 必发一帧，帧里的 SOF 包会把线从 J 拉出去（SYNC 起始就有 NRZI 翻转），计数器每 1ms 清一次，永远够不到 144000。

K 判据为什么定 2.5µs？数据包里的 K 是 NRZI 翻转的结果，一个 K 最多对应 6 连 1（位填充上限）加一位，约 7 个位时间 ≈583ns。2.5µs 的 K 在数据流里出不来，只能是主机的 resume 信令。这个门限顺带满足了指南要求的边沿去抖（建议 4~8 个位时间）。相对主机 resume 的 ≥20ms，2.5µs 的识别延迟可以忽略。

这条判据也有边界：退出挂起只认「K 持续 2.5µs」，所以对「主机不发 resume K、直接发包」这种非规范行为不鲁棒。包内最长连续 K 就是上面那个 583ns，够不到 2.5µs，设备会一直停在挂起态，直到主机复位（SE0 那条支路）才恢复。规范要求主机 resume 必驱 K ≥20ms，这只在非规范主机上出现。

### 2.4 两个标志位

| 标志 | 置位条件 | 清除条件 | 含义 |
|---|---|---|---|
| `connected` | 120 且线是 J | `usb_rst` | 总线空闲态曾经成立 |
| `suspended` | 144000 且线是 J | `rsm_cond` 或 `rst_cond` 或 `usb_rst` | 总线挂起 |

```verilog
assign connected_nxt = usb_rst ? 1'b0 : (con_cond ? 1'b1 : connected);
assign suspended_nxt = usb_rst ? 1'b0 :
                       sus_cond ? 1'b1 :
                       (rsm_cond | rst_cond) ? 1'b0 : suspended;
```

`connected` 有三个用途：它是 `connect_evt` 的载体（上升沿即事件，连上后只报一次）；给挂起判据当前置条件（没连上谈不上挂起）；给复位判据当前置条件（上电时电缆没插、线停在 SE0，不能报一次复位事件，见上文）。它清于 `usb_rst`，也就是 `rst_cond` 那条路要外面并进 `usb_rst` 才能作废附着（见下文）。

`suspended` 有两个用途：门控 `resume_evt`（只有挂起中主机的 K 才算唤醒），以及防止 `suspend_evt` 重复报。它比 `connected` 多列了一条 `rst_cond`：总线复位说明总线刚被主机驱动过，不可能还在挂起；这一位若留着，复位后总线上的 K 会被误判成主机 resume。`sus_cond` 里的 `~suspended` 是语义上的「只报一次」，进了挂起就不再重复报同一段空闲。

`suspended` 的下降沿不是事件，复位和唤醒各有自己的通路。

### 2.5 附着状态与 `usb_rst`

`connected` 只清于 `usb_rst`，也就是 core 复位，软件复位与主机发的总线复位在外面并成这一根。总线复位会把协议状态清掉，设备要重新从总线判一次附着：复位结束总线若回到空闲 J，2.5µs 后重报一次 `connect_evt`，SIE 靠它把 `rcv` 重新拉起来。实测里「长 SE0 期间 `connected` 不动、`usb_rst` 一拍后变 0、回 J 后重新连接」这条链走的就是这个过程。

模块内不另并一条 `rst_cond`。`rst_cond` 只负责出 `usb_bus_rst` 脉冲，清 `connected` 和 `suspended` 是 `usb_rst` 的活。两处在模块内并起来的话，同一个复位会有两条路径去清这两个标志位，集成侧再并一次就是重复。

拔出走的也是这条通路：线拔掉后总线落回长 SE0，够 2.5µs 判出一次 `usb_bus_rst`，这个事件在外面并进 `usb_rst`，附着随之作废；线插回来总线回 J，2.5µs 后重新报 `connect_evt`。剩下的空缺只有「自供电设备拔出后两条线读成 J」那种前端：设备自己的上拉还在，主机不在也看得到 J，判据分不开，要等 `usb_vbus` 进来（见下文）。

### 2.6 事件从 `ref_clk` 送到 `clk12m`

判据在 `ref_clk` 域成立，输出要进 `clk12m` 域。四个事件源分两类，走法不一样：

| 事件 | 载体 | 取法 | 为什么 |
|---|---|---|---|
| `connect_evt` | `connected` | 上升沿 | 标志位，连上后一直保持 |
| `suspend_evt` | `suspended` | 上升沿 | 标志位，挂起后一直保持 |
| `usb_bus_rst` | `rst_tgl` | 异或（新旧不同） | 判据是单拍脉冲，取不了沿 |
| `resume_evt` | `rsm_tgl` | 异或（新旧不同） | 同上 |

标志位这类的两个不用额外做保持：`connected` 由 `con_cond` 置起、只清于 `usb_rst`，`suspended` 置起后最少也保持 120 拍，都是长电平，同步链一定采得到。判据那类是 `ref_clk` 域的单拍脉冲，直接同步采不到，改成翻转通知：

```verilog
// ref_clk 域：判据单拍 → 翻转一次
assign rst_tgl_nxt = rst_cond ? (~rst_tgl) : rst_tgl;
assign rsm_tgl_nxt = rsm_cond ? (~rsm_tgl) : rsm_tgl;

// clk12m 域：两拍同步，异或出新旧不同 = 一个脉冲（输出组合直出）
assign rst_s_nxt[1:0] = {rst_s[0], rst_tgl};
assign usb_bus_rst    = rst_s[0] ^ rst_s[1];
```

翻转位在源域是持续电平，同步链一定采得到，两拍之差就是一个脉冲。两次同类事件至少隔 2.5µs，比一个 `clk12m` 周期长得多，不会两翻相消（用例 `bs_two_resets` 覆盖）。

两个翻转位只吃 `ref_rstn`，不吃 `usb_rst`。原因很直接：`usb_rst` 要是清它，`clk12m` 侧就会看见一次跳变，凭空多出一个事件脉冲。它不表示任何状态，只是「刚发生过一次」的载体。

`clk12m` 侧的四个输出是组合直出，这是 `code_rtl.md` 规则 6 的显式例外：它们只送同域的 SIE，不直连 pad、不进模拟 PHY、也不跨域，规则 6 要寄存的那三条理由一条都不沾。取沿的两位是同一个同步链上的相邻触发器，每个 `clk12m` 沿最多变一位，与和异或都不会出毛刺；脉冲宽度就是 1 个 `clk12m` 周期。

两个域都由 `ref_clk` 派生、上升沿对齐（`clk12m` 的两个来源 `dclk` / `clk12s` 都在 `ref_clk` 域寄存产生，见上文），所以这两拍同步不是为了防亚稳，是为了对齐边沿。`clk12m` 侧只吃 `ref_rstn`，不混 `usb_rst`，一个域里不混两种复位（见下文）。

`bus_suspended` 是这一节的第五个输出，也是唯一一路电平。它就是 `sus_s` 链的输出级（`sus_s[0]`），边沿与 `suspend_evt` 同一拍：`usb_tx_serial` 的唤醒旁路判的是「总线已挂起 + SIE 请求唤醒」，挂起这件事的源在这里，旁路直接读它比读 SIE 回送的副本少一次往返（见 [tx_serial_design.md](tx_serial_design.md)）。它跟着 `sus_s` 只吃 `ref_rstn`，所以 `usb_rst` 把 `suspended` 清掉之后，这一侧还要 1~2 个 `clk12m` 拍才跟下来，那几拍读到的是旧值——与 `suspend_evt` 是同一笔口径，无实际影响：同一时刻 `sie_wkup` 也在被清。

### 2.7 唤醒的两条路径

| 阶段 | 谁在驱总线 | 本模块做什么 | `resume_evt` |
|---|---|---|---|
| 远程唤醒 ① 设备驱 K 1~15ms | 设备 | 用 `tx_en` 挡掉自己驱的 K | 不置 |
| 远程唤醒 ② 设备交高阻、主机接管驱 K | 主机 | 仍 `connected`+`suspended`，判 `rsm_cond` | 置脉冲，`suspended` 落 0 |
| 主机主动 resume | 主机 | 判 `rsm_cond` | 置脉冲，`suspended` 落 0 |

远程唤醒要分两段看。第一段的驱动链在 SIE 和 `usb_tx_serial`：软件写寄存器、SIE 拉 `sie_wkup`，
`usb_tx_serial` 走挂起旁路（`bus_suspended`/`sie_wkup` 直压 `tx_bit`/`tx_en`，不占状态机；见
[tx_serial_design.md](tx_serial_design.md) 的「挂起与远程唤醒的 K 驱动」）。旁路的挂起条件用的是本模块判出的
`bus_suspended`，所以这两段的状态来源是同一个：设备自己驱的 K 期间本模块看到的结果是 `tx_en`，
驱动器在驱，于是计数器清零、判据被挡，这段 K 不会出 `resume_evt`，`suspended` 也保持 1。

第二段是主机接管的 K。设备交高阻之后，规范要求主机在 10ms 内开始驱 K ≥20ms 接管总线，
这段 K 是主机驱的：`tx_en` 已经落下，设备仍是 `connected`+`suspended`，计数器从零起算，
够 2.5µs 就判出 `rsm_cond`，`resume_evt` 照常出，`suspended` 跟着落 0。所以远程唤醒走完，
软件拿到的仍是 `resume_evt`，只是它出现在主机那段 K 上，不在设备自己驱的那段。

第一段为什么不置 `resume_evt`，三条理由：

1. 软件对自己的动作不会意外。查过的四家都不给设备自发 K 报事件：ST 的 `CNTR.RESUME`、
   GD32 的 `DCTL.RWKUP` 只在控制寄存器里，中断寄存器没有对应位；NXP LPC 把远程唤醒做成
   「往 `DEVSTAT.SUS` 写 0」这个动作；Renesas 的 `DVST` 报的是 `DVSQ` 状态迁移，而设备
   自发 K 期间 `DVSQ` 仍停在 Suspend，没有迁移可报。
2. 驱 K 的那一刻总线还没恢复。规范里 resume 是主机驱 K ≥20ms 接管总线，设备驱的 1~15ms
   只是个唤醒请求。此刻 `suspended` 还是 1，如果同时置 resume 标志，软件读到的就是
   「resume 已发生、`suspended` 仍为 1」这组自相矛盾的状态。
3. 会诱导软件提前动作。resume 中断服务程序要做的是退低功耗、恢复收发、准备收包。
   让它在设备自己驱 K 期间被叫醒来做这些，就抢在主机的 20ms K 之前动了，设计指南里讲远程唤醒那一节明确禁止。

远程唤醒要发 K，规范有三个前置条件：

| 前置条件 | 规范要求 | 谁判 |
|---|---|---|
| 设备已挂起 | 总线连续 idle ≥5ms（TWTRSM）才可发起 | 硬件出 `suspended`（idle >3ms），软件再补 ≥2ms |
| 特性已被使能 | 描述符声明 + `SET_FEATURE(DEVICE_REMOTE_WAKEUP)`；总线复位后必须禁止 | APB 寄存器位（如 `rw_en`），复位清 0 |
| K 时长与收尾 | 保持 1~15ms，结束后交高阻，不驱到 J | SIE（计时）+ `usb_tx_serial` 的唤醒旁路（执行） |

第一条口径要注意：规范写的是「连续 idle ≥5ms」，而我们的 `suspended` 在 idle >3ms 时就置起了，所以软件看到 `suspended` 之后还要再等 2ms，或者自己从 idle 起算满 5ms。

第二条属于复位口径：总线复位必须把 `rw_en` 清 0，复位之后主机不重新使能就发不出 K。这条落在寄存器层，与「附着状态与 usb_rst」里那两个标志位的复位范围是两回事。

第三条分两半：时长由 SIE 计（1~15ms），收尾由 `usb_tx_serial` 天然满足，`sie_wkup` 一落，下一拍 `tx_en` 就落 0，驱动器交高阻，不会停在 J。

前两条硬件都不判。`wkup_req` 直接进唤醒旁路，本模块和 SIE 都不与 `suspended` 相与。软件读 `suspended` 状态位、自己维护 `rw_en` 就够了，判断成本为零；硬件相与反而会把请求静默吞掉，调试时查不出「为什么没发」。

### 2.8 复位口径

| 复位 | 作用域 | 极性 | 来源 | 复位范围 |
|---|---|---|---|---|
| `ref_rstn` | 全模块 | 低 | 上电/系统复位 | 全部寄存器 |
| `usb_rst` | `ref_clk` 域 | 高 | core 复位（软复位 ∪ 总线复位，在外面并好），集成位置待定 | 计数器、两个标志位 |

`usb_rst` 按同步复位处理，只进 `ref_clk` 域；`clk12m` 侧那几条同步链与两个翻转位只用 `ref_rstn`，一个域里不混两种异步复位。

CPU 的软件复位（APB 写 `SWRST`）由 APB 侧产生脉冲，与判出的总线复位在外面并成这一根。它只复位 USB core，不上总线、不驱 SE0，本模块既不产生也不分发它。

### 2.9 可综合性与正确性说明

判据部分单时钟（`ref_clk`）、异步复位低有效，输出同步链另在 `clk12m`。纯组合加时序，无 `#` 延迟、无 `initial`、无 latch、无异步电路。计数器饱和靠比较加自保持实现（`cnt_nxt = cnt_at_top ? cnt : cnt + 1`），不需要额外的使能逻辑。

唯一的跨时钟输入 `tx_en` 组合直连（见上文）。它来自 `clk12m` 域，而 `clk12m` 的两个来源都由 `ref_clk` 寄存产生，属同步派生时钟之间的交接，综合不会推断出异步路径。

## 4. 关键设计点描述及波形

波形截图放在 `doc/fig/busstate_*.png`，正文用超链接引用，不内嵌。图里同时有果（结论所在的
信号）和因（导致它的信号，通常是 `cnt`、门限命中和线状态）。完整用例与覆盖率见
[bus_state_verification.md](bus_state_verification.md)。

### 4.1 一条计数器为什么够

**问题**：2.5µs 门限有三个（连接 J、复位 SE0、唤醒 K），再加 3ms 挂起，按直白的写法要四条计数器，面积和复位范围都跟着翻。

**设计做法**：四条判据真正依赖的量只有一个，就是「线保持了多久」，再配上当时的线状态和两个标志位。线变化清零保证计数值的含义永远是「距上次线变化多少拍」，这个量对三个 2.5µs 判据是共用的，3ms 只是它的另一个刻度。

**实测**：`bs_threshold_scan` 前后各静置 200 拍 J，中间给一段定长 SE0 或 K，121 拍不出事件，122 拍出，再长也只出一次。多出的 2 拍是固定流水，`line_s` 打的那一拍（在上游的 `usb_rx_deserial` 里）占 1 拍，线变化那一拍计数器被清、下一拍才开始累加。输出落在第 122 拍时，线上的电平正好是 2.5µs 整。

📎 [图：门限与计数（busstate_connect_threshold.png）](../fig/busstate_connect_threshold.png)

上图里线一直保持 J，`cnt` 一路爬，`cnt_2p5u` 只在到门限那一拍为高（20.8ns），`con_cond` 与它同拍，`connect_evt` 等同步链走完才出 1 拍脉冲。

### 4.2 自己的发送不会被当成主机活动

**问题**：我们自己也在线上驱电平。包尾 EOP 是 SE0（≈160ns），远程唤醒是 K（1~15ms），这两种要是被自己的判据吃进去，就成了自己发的 K 把自己唤醒、自己的 EOP 被当成总线复位。

**设计做法**：`driving` 期间清计数器，四个判据再各带 `~driving`（见上文）。门控只挡设备自己驱的那一段，主机后来接管的 K 不受影响（见上文）。

**实测**：`bs_self_drive` 里 `tx_en=1` 期间线被驱成 K 持续 1ms，远过 2.5µs 门限，`rsm_cond` 恒 0、`resume_evt` 无脉冲、`suspended` 保持 1；另一景自驱 SE0 也不发 `usb_bus_rst`。撤驱动后主机再驱 K 400 拍，`resume_evt` 照常出，`suspended` 落 0，这段就是远程唤醒的后半段（见上文表里第 ② 行）。

📎 [图：自驱 K 期间判据被挡（busstate_self_drive.png）](../fig/busstate_self_drive.png)

### 4.3 SOF 破挂起

**问题**：总线空闲 3ms 就算挂起，可主机每 1ms 都要发一个 SOF，帧间的 J 到底能不能累计到 3ms。

**设计做法**：SOF 包会把线从 J 拉出去（SYNC 起始就有 NRZI 翻转），计数器每 1ms 清一次，永远够不到 144000。

**实测**：`bs_connect` 的前后文窗口加 `bs_k_when_awake` 一起看：不到 3ms 的 J 静置不产生 `suspend_evt`，也不重报 `connect_evt`；中间插一段 100µs 的长 K 把计数器打断后，线回 J 从零重新起算，够 3ms 照常出 `suspend_evt`（三处计数 1/1/1）。打断前的拍数不会被累进来。

### 4.4 复位门限与 EOP 的量级间隔

**问题**：同一个 SE0，包尾 EOP 是 ≈160ns，复位是 ≥2.5µs，两者只能靠时长分开，门限得离 EOP 足够远。

**设计做法**：这里取 120 拍（2.5µs），EOP 那边是 8 拍（160ns，来自 `rx_deserial` 的 `EOP_WIDEN_MAX`），差 15 倍。

**实测**：116..121 拍的 SE0 一条事件都不出，122 拍起出 `usb_bus_rst`（见上文那段扫描）；160ns 量级的 SE0 离门限差 15 倍，够不到。短 K 同理，`bs_short_k` 里 28 拍的 K 不出 `resume_evt`，挂起保持。

📎 [图：SE0 门限与判据链（busstate_bus_rst.png）](../fig/busstate_bus_rst.png)

### 4.5 一次 SE0 只出一个 `usb_bus_rst`

**问题**：主机复位时 SE0 会持续 10ms，判据在这段时间里一直成立，只报一次得有个结构上的保证，不能靠「大概只匹配一拍」。

**设计做法**：计数上界取 121，`cnt == 120` 就这么一拍；长 SE0 也不会去匹配 3ms 那条判据（它要求线是 J）。

**实测**：`bs_bus_rst` 里 10ms 的 SE0 只出 1 个 `usb_bus_rst` 脉冲，紧接的第二个 10ms 窗口判据和脉冲都是 0；线回 J 后 6.25µs 不重报 `connect_evt`，因为 `connected` 还在。

### 4.6 脉冲的宽度与延迟预算

**问题**：判据在 `ref_clk`，输出在 `clk12m`，中间还隔着两拍同步链；`clk12m` 走 `dclk` 时周期会抖，宽度和延迟都不能只靠推算。

**设计做法**：两个域边沿对齐（见上文）。宽度由「每个 `clk12m` 沿最多变一位、异或不成毛刺」保证；延迟下界 1 个 `ref` 拍、上界一个 `clk12m` 周期，由同步链的相位决定。

**实测**：宽度上，所有用例的所有脉冲都是 1 个 `clk12m` 拍（≈83.3ns），`bs_clk_jitter` 把周期按 3/4/5 拍轮转也一样，两拍同步链只依赖「边沿对齐 `ref_clk`」，不依赖周期恒定。延迟上，`bs_latency_phase` 把触发事件的那次线变化平移 0..3 拍，扫遍 `clk12m` 的四个相位，四类事件的读数一致：

| 相位 p | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 判据 → 脉冲（`ref` 拍） | 3 | 2 | 1 | 4 |

范围 1..4 `ref` 拍，上界 4 拍就是一个 `clk12m` 周期 ≈83ns。这是 SIE 侧握手要留的余量。

### 4.7 集成缺口（本次一并登记）

**问题**：本模块之外还有三处没接上，不登记的话会在集成阶段才暴露。

**设计做法**：按「现状 / 需要的动作」列在下面。

| 项 | 现状 | 需要的动作 |
|---|---|---|
| `usb_rst` 的集成位置 | 输入已定（core 复位），在外面并好 | 定集成点，复核会不会与 `usb_bus_rst` 打架 |
| 四个脉冲送 `pclk` 寄存器堆 | clk12m 单拍 ≈83ns，只有 2 个 `pclk` 周期 | 由 SIE 侧事件汇聚按「单向通知」口径展宽 |
| 自供电设备拔出的判别 | 线仍读成 J，判据分不开 | 等 `usb_vbus` 输入 |
