## 1. 概述

`usb_tx_serial` 把 SIE 给的**字节流**变成线上 NRZI 位流：SYNC → 逐字节（位填充）→ EOP，
输出 `tx_bit`/`tx_se0`/`tx_en` 三个数字信号给 APB 侧的模拟 PHY。1× `clk12m` 域，一拍 1 bit。

验证目标：在**正常包 / 全字节值 / 边界形态 / 中止 / 随机形状**下证明——

1. **位流保真**：线上位流 = 独立 oracle 算出的理想位流（逐位比对，含填充插入位置）；
2. **字节保真**：回环（TX → 理想 PHY → CDR → deserial）收到的字节 = 发出的字节，
   且每包 `tx_ready` 脉冲数 = 字节数；
3. **填充规则**：连续 6 个 1 后**恰插一个 0**，插 0 拍 hold（不移位、`bit_cnt` 不前进）；
   计数**从 PID 起算**（SYNC 不参与），且**跨字节累计**；
4. **帧定界**：`tx_se0` 恰 2 拍（166.7ns，规范 160–175ns）+ J 恰 1 拍 + `tx_en`↓ 交高阻；
   包尾严丝合缝，无排空余量、无多余 hold；
5. **中止与恢复**：任意发态 `tx_active`↓ → 线上回 J、状态无残留、紧随的重发包完全正常；
6. **挂起与远程唤醒**（2026-09-22 增）：挂起期驱动器交高阻（线由偏置给出 J）、
   `sie_wkup`=1 时线上驱 K 且**不被接收链解成帧**、撤下后回高阻；
   唤醒期 SIE 不发 `tx_active`/`tx_data`（§2.11 契约）；违约时驱动器也压得住（§4.12 段 4 的记录）。

**本模块无 MODE 派生需求**，只有一份 RTL 定稿、20 个用例各跑一次。

**PHY 模型的建模口径**（设计报告 §4.8.2）：`tx_en=0` 的高阻态建模为**空闲 J**（总线上有主机
15kΩ 下拉 + 设备 1.5kΩ 上拉，分压结果就是 D+ 高 / D- 低），`tx_se0=1` 时忽略 `tx_bit` 给 SE0。
模型是纯组合、零延迟的理想模型——模拟域的斜率/抖动归 CDR 容差管，本模块不重复覆盖。

> ★ 回环里 `usb_rx_deserial` 的 `tx_active`/`rx_abort` **必须接 0**：那是自收发门控，
> 直连会把它一直摁在 `USB_IDLE`、什么都收不到（USB 半双工，同一时刻只有一个方向驱动总线）。

### 3.1 因果链打印（`causal_*` 记录器 + `causal_print`）

按 `sim/common/README`「仿真结果确认规范」的 **因→变→果 + 前后窗 + 量化判据** 三段式落地：
在 `posedge clk12s` 采 DUT 的 `tx_stat_cur` 迁移记拍号、记 `tx_done` 与回 `S_IDLE` 拍号、
记本包插 0（hold）拍数；前窗 = 包起前"线 J 且 DUT 停 `S_IDLE`"的**连续拍数**，
后窗 = `tx_done` 后同类连续拍数。**只打印、不改任何断言**（20 用例 PASS/FAIL 语义与加打印前一致）。
旗舰用例各挂一条，例如 `sim_tx_pid_carry.log`：

```
因果链·[pid_carry/E1_07] 前窗: 包起前线保持 J 且 st=S_IDLE 共 4 拍 (干净空闲起点, 判据 >=2)
因果链·[pid_carry/E1_07] 因:   tx_active↑ @cyc 4 → st S_IDLE→S_SYNC @cyc 5
因果链·[pid_carry/E1_07] 变:   st S_SYNC→S_DATA(DATA_LAST) @cyc 13 (SYNC 移完, 载首字节 + tx_ready); 数据段→S_EOP1 @cyc 31 (末字节+尾填充移完)
因果链·[pid_carry/E1_07] 变:   本包插 0 (hold) 拍数 = 1 (判据: 等于 oracle 位流里的填充 0 个数)
因果链·[pid_carry/E1_07] 果:   tx_done @cyc 32 (EOP 的 J 拍, 与回 S_IDLE 同拍); tx_en↓ @cyc 33 → 交高阻 (tx_en 是寄存器, 条件 st==S_IDLE, 故晚 tx_done 一拍)
因果链·[pid_carry/E1_07] 后窗: tx_done 后线保持 J 且 st=S_IDLE 共 6 拍 (判据 >=4: 交高阻=电气空闲 J)
```

可复算的量化读数：`S_SYNC→S_DATA` 与 `S_IDLE→S_SYNC` 相差 **8 拍**（SYNC 恒 8 拍，§2.5）；
`E1_07` 插 0 = **1**（跨字节 `3+3=6`，§2.5 反例）；中止包印"数据相位与 EOP 相位均未到达"。

### 3.2 输出 DFF 直出的结构守卫（第 10 条断言）

规则 6 要求四个输出寄存器直出，功能回归**证不了**这条——它管的是"这条表达式写在寄存器里
还是写在 `assign` 里"，与位流对不对无关。所以单加一条结构断言：记录每个 `posedge clk12s`
的 `$time`，再对每个输出用 `always @(tx_bit)` 之类的敏感表触发，比对"本次变化时刻"是否
等于"最近一次时钟沿时刻"：

```verilog
integer last_edge_t = -1;                       // 最近一次 clk12s 上升沿时刻
always @(posedge clk12s) last_edge_t = $time;   // 阻塞赋值, 只在本时钟这一处写

task out_edge_check(input [255:0] sig_name);    // 变化点必须落在时钟沿上
    begin
        if (ref_rstn && (last_edge_t >= 0) && ($time !== last_edge_t)) begin
            $display("    FAIL: %0s 在非 clk12s 沿变化 (@%0t, 最近沿 %0t) —— 不是 DFF 直出",
                     sig_name, $time, last_edge_t);
            errors = errors + 1;
        end
    end
endtask
always @(tx_bit)   out_edge_check("tx_bit");
always @(tx_se0)   out_edge_check("tx_se0");
always @(tx_done)  out_edge_check("tx_done");
always @(tx_ready) out_edge_check("tx_ready");
```

**只覆盖 `tx_bit`/`tx_se0`/`tx_done`/`tx_ready` 四个纯译码输出，不含 `tx_en`**：`tx_en` 是
唯一带边沿条件的输出（`D` 里有 `tx_active` 这个**输入**），它的 D 无法由现态译码得到，
规则 6 归到"兜底"一类、另有豁免条款（§5.4）。

> 这条断言**替换掉了**两处已失效的旧断言：① `tx_en === tx_active` 直通契约（新设计的
> `tx_en` 是寄存器，契约本身不成立，§5.4）；② "每个时钟沿重算改造前的组合式与
> `tx_bit`/`tx_se0` 比对"（那是 2026-09-17 次态译码方案的等价性断言，2026-09-20 换现态
> 译码后输出本就整体后移一拍，逐拍等价不再成立，见 §4.9）。

### 4.1 单字节包基线（`tx_pid_only`）

ACK 包（SYNC + `0xD2` + EOP）的因果链读数：前窗 4 拍干净空闲；`tx_active↑ @cyc4` →
`S_IDLE→S_SYNC @cyc5` → **8 拍后** `S_SYNC→S_DATA @cyc13`（载 PID + `tx_ready`）→
数据段完 @cyc22 → `S_EOP1 → S_EOP2 → S_IDLE`，`tx_done @cyc23`（**与回 `S_IDLE` 同拍**），
`tx_en↓ @cyc24` 交高阻，后窗 6 拍。位流恒 16 位（8 + 8，无填充），回环 1 字节相等。
**基线站得住，后面各条才有意义。**

> 单字节包的形态是 `S_SYNC → S_DATA_LAST`（PID 即末字节，没有中间数据态），所以日志里
> 印的是 `S_SYNC→S_DATA(DATA_LAST)`；多字节包才会看到 `S_DATA` 停留（§4.5）。

**波形（与上日志同源 VCD，`tx_pid_only.vcd`）**：

📎 [图：单字节包整链（tx_serial_pid_only.png）](../fig/tx_serial_pid_only.png)
&nbsp;`tx_active↑` → `S_IDLE→S_SYNC` → 8 拍后 `S_SYNC→S_DATA_LAST`（同拍载 PID、`tx_ready` 脉冲）
→ `S_EOP1/S_EOP2` → `tx_done`（与回 `S_IDLE` 同拍）→ `tx_en↓` 交高阻；位流恒 16 位、无填充。

### 4.2 位填充：插一个 0 + hold 一拍（`tx_stuff_dense` / `tx_stuff_pos_scan`）

- `tx_stuff_dense`：12×`0xFF` 连发，末条位流 **144 位**（纯数据 8×15=96 位，其余为插入的 0）。
- `tx_stuff_pos_scan`：构造字节让第 6 个连 1 恰好落在字节内每个位置，末条位流 **104 位**，
  与 oracle 的括号参考值一致——**每个相位上的 hold 逻辑都对**。
- 图上可直接看到插 0 的两拍相邻关系（📎 [tx_serial_stuffing.png](../fig/tx_serial_stuffing.png)，
  VCD 逐拍实测）：`bit_ones_cnt` 累到 `3'b110`(=6) 那拍 `bit_stuff`=1 → **下一拍**线上强制插 0
  （`tx_bit` 翻转、`bit_ones_cnt` 清 0），且该拍 `data_shift_en`=0、`data_shift` 不动、
  `bit_cnt` **不前进**。逐拍数值：

| 拍 | … | k（第 6 个连 1） | k+1（插 0 拍） | k+2（恢复） |
|---|---|---|---|---|
| `bit_cnt` | … | 4 | **4（停）** | 5 |
| `bit_ones_cnt` | … | 6 | **0** | 1 |
| `bit_stuff` | … | **1** | 0 | 0 |
| `data_shift` | … | `1111` | **`1111`（不移）** | `111` |
| `tx_bit`（线上） | … | 1 | **0（插的 0）** | 0（下一数据位 1 = 保持） |

k+2 那拍的 `tx_bit` 仍是 0：线上那位是**数据 1**，NRZI 规则是"1 = 保持"，所以电平不动。

### 4.3 末字节正好 6 连 1 收尾（`tx_tail_stuff`）

末字节 `0xFC`（线上 b2~b7 全 1 = 恰 6 连 1）：位流 **25 位** = 8(SYNC) + 8(PID) + 8(数据) + 1(收尾填充 0)，
第 25 位必须是 0，之后才发 SE0。`0xFD` 同判。长包末尾 `FF FF FC` 与阴性对照 `00`（24 位、无填充）
都过，累计位不符 **0**。

**插入位置落在 `S_EOP1` 里**（设计报告 §2.6 关键点②）：末字节移完时 `bit_ones_cnt` 恰好是 6，
`S_DATA_LAST` 因此**不**直接转 EOP，而是先转进 `S_EOP1`；`S_EOP1` 见到 `bit_stuff`=1 就
**原地自环一拍**把 0 插掉（这一拍 `tx_se0` 被 `bit_stuff` 压住、不发 SE0），下一拍才真正进
SE0 段。VCD 逐拍：`S_EOP1` 停留 **2 拍**（首拍 `bit_stuff`=1、插 0；次拍 `tx_se0`↑），
随后 `S_EOP2` 一拍，SE0 合计仍是 **2 拍 = 166.7ns**（§4.4）。对照 `0x00` 收尾时
`S_EOP1` 只停 1 拍。

**这条是"包尾严丝合缝"的直接验收**（设计报告 §4.1）：因为没有 FIFO 缓冲，欠下的填充 0
必须在**进入 SE0 之前**补发，不能拖到 EOP 里（否则 EOP 时序就不合规范了）。

### 4.5 跨字节连 1 累计（`tx_pid_carry` / `tx_carry_sweep`）

位填充最难的边界是**跨字节**：前一字节约尾巴的连 1 要带进下一字节的头部（设计报告 §2.5 反例）。

- `tx_pid_carry`：OUT token（PID `0xE1`，线上尾 3 连 1）发给地址 7（次字节 `0x07` 线上头 3 连 1）
  → 3+3 = 6 → **必须插一个 0**。位流 25 位，第 20 位（插入位）为 0，`0x07` 的 bit3 被推迟到第 21 位。
  阴性对照 `0xE1 + 0x00` 位流恰 24 位（不该插位）。
- `tx_carry_sweep`：16 PID × 16 次字节全组合，256 组里 **17 组在边界插填充、239 组不插** ——
  统计分布证明这批用例真的扫到了"该插/不该插"两种结果，而不是全部退化成同一种。

**波形（`tx_pid_carry.vcd`，跨字节边界那一段）**：

### 4.6 全字节值扫描（`tx_byte_sweep`）

### 4.7 中止路径（`tx_abort` / `tx_abort_phases`）

`tx_active` 中途撤掉后，DUT 在**下一个** `clk12m` 沿回 `S_IDLE` 并复位 NRZI 到 J，
不留残留填充/半字节；六相位（`S_SYNC` / `S_DATA` / `S_EOP1` / `S_EOP2` / 正在插填充 0 那拍 /
`S_DATA_LAST`）各中止一次，每次之后紧接重发一包，全部正常。

**六相位不是凑数**：FSM 从 4 态扩到 6 态后多出两条合法弧（`S_DATA_LAST→S_IDLE`、
`S_EOP1→S_IDLE`），合并 19 个用例的迁移矩阵发现**这两条一条都没走到**——是激励缺口不是
不可达分支，故各补一个相位（见 `case_abort_phases.v` 的相位 5/6 注释）。补完后合法弧
**16/16** 全中（§8.3）。相位 6 的触发点很讲究：`tx_active` 是 TB 侧寄存器，必须在
"**将要**进 `S_EOP1`"的那一拍撤（末字节态 `bit_cnt==7` 且非填充拍），否则撤晚了只走得到
`S_EOP2→S_IDLE`。

**相位 6 的判据与其它五个不同**：中止点落在末字节**最后一位之后**，线上已经走完
SYNC + 整个 PID —— 这种截断片段在接收侧是合法字节序，RX 只能靠自己 14 拍关帧超时收尾，
会报出一个**无错帧**。这不是 TX 残留（那一段本来就是"像样的"内容，缺的只有 EOP），
所以 `no_valid_frame` 在此不适用，改为**直接钉 TX 侧语义**：中止窗口内 `tx_se0` 高 0 拍、
`tx_done` 脉冲 0 个、`tx_ready` 脉冲恰 1 个（PID 已取走）。日志实证：
`说明[eop1_abort]: RX 新增 1 帧 (超时收尾), 末帧 1 字节 —— 片段内容合法、只是没有 EOP, 属预期`。

**关于"幽灵帧"**：中止必然在线上留一个**截断包**，RX 会进帧再掉出 —— 这是截断包的正常收场，
不是 TX 残留。所以其余五个相位的正确断言是"新出现的帧**全部被 RX 判错**"
（`no_valid_frame` 要求 `err_frames` 增量 = `rx_frames` 增量），而不是"完全不出现新帧"。
日志实证：`说明[data_abort]: 截断帧 1 个 / 末帧 4 字节, RX 全部判错 → 无残留`。

**撤请求后并非"当拍"交高阻**（`tx_en` 是寄存器，§5.4）：VCD 实测 `tx_abort` 的第 3 次中止，
`tx_active`↓ @1927145 ps，`tx_stat_cur` 到下一沿 @2010481 才回 `S_IDLE`，
`tx_en`↓ @2093817 —— **比 `tx_active`↓ 晚整 2 拍**（166672 ps），期间多驱动 2 位数据位
（其中末位是"滞留"的：它由已决定收尾的状态译出）。这是规则 6 现态译码在中止路径上的
**已知代价**（设计报告 §2.10 已记账）；正常 EOP 收尾不受影响——`tx_en`↓ 落在 `tx_done`
后一拍，与 2 拍 SE0 严丝合缝（§4.4）。

### 4.8 随机压测（`tx_random_stress`）

固定种子 300 包，包长 2~17 字节，1/4 概率把数据字节换成长连 1 形态（`0xFF`/`0xFE`/`0xFC`），
末字节取反以随机化收尾填充形态。每包同跑回环 + 逐位 oracle。

换种子各跑一遍全过：`1` / `12345` / `12345678`(默认) / `ffffffff` / `deadbeef`。

> 这条是**防回归**用的：本模块两个已修缺陷都落在"跨字节边界 + 字节末位 + 连续多字节填充"
> 这一片形状空间里（§5），随机撒网是覆盖这片最便宜的方式。

### 4.9 现态译码的代价：位流不变、拍号整体后移（2026-09-20 设计复跑）

**结论：位流、包长、字节序全不变；变的只是各个输出的**拍号**（整体后移一拍）与
`tx_ready` 后移造成的 SIE 余量少一拍。**判据独立于内部信号：19 个用例的**功能判据一字未改**
（位流逐位 oracle、回环字节、EOP 秒数、脉冲计数）全部 19/19 PASS。

| 量 | 旧（组合/次态译码） | 新（现态译码） | 有无变化 |
|---|---|---|---|
| 线上位流（位数、每位值、字节序） | 参照 | 完全相同 | **无** |
| 包长（SYNC 8 + 数据 + 填充 + EOP 2 拍） | 参照 | 完全相同 | **无** |
| `tx_se0` 宽度 | 166672 ps | 166672 ps | **无** |
| 相邻 `tx_ready` 脉冲间距 | 8 / 9 / 10 拍 | 8 / 9 / 10 拍 | **无**（两端一起移） |
| SIE 从见 `tx_ready` 到须备好下一字节 | 8 拍 | **7 拍** | **少 1 拍**（§2.8 已记账） |

新设计的 SOP 实测（`tx_pid_only` 的 VCD，`BIT_TIME = 83336 ps`）：
`tx_active↑ @760441` → `tx_en↑ @843777`（第 1 拍）→ `tx_bit` 翻 K `@927113`（第 2 拍），
即从请求到 SOP 共 **2 拍**——其中 1 拍是 `S_IDLE→S_SYNC` 的状态迁移，另 1 拍是
`tx_bit` 作为寄存器输出的固有延迟。

- **为什么拍号变了位流却不变**：现态译码只改输出的**相位**，不改每个状态算出来的**值**。
  同一条表达式晚一拍出，于是每一位仍占满一拍、状态推进的**相对**间距不变——接收端看到
  的还是同一串位。合成迁移矩阵可以核对：状态停留拍数与旧设计逐项相同（§8.3）。
- **为什么 SOP 是 2 拍而不是 1 拍**：`tx_bit` 本身是寄存器，状态进了 `S_SYNC` 还得再等一拍
  才把 K 送上线。这一拍不影响任何协议余量（`tx_active` 由 SIE 提前给足），也不影响位序。
- **`tx_ready` 间距不变但余量少一拍**：脉冲间距 8/9/10 是"载入→载入"的固有周期，
  两端一起后移所以不变；而 SIE 是拿"看到脉冲"当起跑枪，起跑枪晚响一拍、终点不动，
  余量自然从 8 拍变 7 拍。`tx_handshake` 实测最小间距仍是 **8 拍**（该用例量的是脉冲间距，
  不是余量），与设计报告 §2.8 的记账口径一致。

### 4.10 波形复查：数据字节 `8'h70` 的移位（2026-09-18，用户提出）

**结论：移位与位序正确，RTL 无需改动。**

- **因**：`8'h70` = `0b0111_0000`，LSb-first 送上线的位序应为 `0 0 0 0 1 1 1 0`。
- **变**：一次性诊断 TB（`sim/tx/scratch/dbg_70.v`，`iverilog -g2012 -o dbg_70.vvp

### 4.11 `tx_last` 契约：与末字节同拍拉起、**见该字节的 `tx_ready` 即可落**（2026-09-21，用户定）

**结论：SIE 侧最省事的做法（看到末字节的 `tx_ready` 就落）就是合法做法，TB 取这个最紧的做法。**

**为什么合法**：`tx_last` 只在 `S_SYNC`/`S_DATA` 的**字节载入边界**被采样（RTL L129/L133）。
末字节载入后 FSM 进 `S_DATA_LAST` 并自环 8 拍，**全程不再引用它**；`tx_ready_nxt`/`tx_done_nxt`
也不含它。而 `tx_ready` 是寄存器、出现在**载入之后那一拍**（§2.10）——所以"SIE 看到 `tx_ready`
才落"必然晚于"DUT 最后一次采样"至少一整拍，**落点有一拍余量**。

**因 → 变 → 果**

| 段 | 内容 |
|---|---|
| 因 | DUT 只在末字节载入那一拍采样 `tx_last`；`tx_ready` 在该拍之后一拍才出 |
| 变 | TB 的 SIE 侧模型用 `last_taken`：末字节的 `tx_ready` 那拍置起 → 下一拍把 `tx_last` 落掉 |
| 果 | 19/19 PASS；位流位数、逐位 oracle、回环字节、EOP 拍数与"保持到包尾"的模型**逐位相同** |

复跑命令：`make -C sim/tx run`。**落点窗口的实测边界**（下面第 2 条）：只对**多字节包**敏感，
且只敏感"提前"这一个方向——晚落多久都行。

**反向验证（证明这条判据不是空转，也钉住"只能晚不能早"）**：把 TB 的 `last_taken` 改成
**见任何 `tx_ready` 就置起**（off-by-one，等于把 `tx_last` 提前一拍落），复跑：

| 用例 | 结果 | 现象 |
|---|---|---|
| `tx_pid_only`（1 字节包） | **PASS** | 末字节就是首字节，落点仍在 `S_DATA_LAST` 之后 → 单字节包对这个错**不敏感** |
| `tx_pkt_all` / `tx_len_scan` | FAIL（13 / 18 errors） | 包被截断，位流位数与回环字节数双双不符 |
| `tx_pid_carry`（2 字节包） | FAIL（22 errors） | `FAIL[carry]: 等不到 tx_done (TX 挂死)`，FSM 卡在 `S_DATA` 899954 拍 |

即：**提前一拍 = 多字节包的末字节被判成普通字节 → 包永不收尾 → 挂死**；晚落则完全无害。
TB 因此取"见 `tx_ready` 即落"（最紧），SIE 只要不比它更早就都合法——**给 SIE 留的是单向余量**。

### 4.12 挂起交高阻与远程唤醒 K（`tx_susp_wkup`，2026-09-22 用户提需求）

结论：挂起期驱动器确实交高阻，`sie_wkup` 确实驱 K，而且这条旁路对包路径有优先级。

被测的是设计报告 §2.11 的两根电平输入。用例分 6 段，每段一条独立的量化判据，
不是"K 电平看着对"就收工。

因 → 变 → 果（三段主线，日志原文见 `sim_tx_susp_wkup.log`）

| 段 | 因 | 变 | 果（量化判据） |
|---|---|---|---|
| 挂起 | `bus_suspended`↑ @cyc 46（线已在 idle、`tx_en` 已为 0） | `tx_en` @cyc 47 = 0 | 挂起 40 拍内 `rxdp/rxdn` 恒 J（1/0）、`rx_frames` 无新增 |

只查电平的话，一个"顺手发出半包"的实现也能骗过检查。这条阴性判据与电平判据是成对的。

段 4 是**契约外的一次刻意违约**，只作记录、不作设计要求。契约（§2.11）写明唤醒期间 SIE 不发

`S_IDLE`（走到 `S_DATA`），但 `tx_en` 仍为 0、线上无残留。也就是说违约不会把包发出去，
这是旁路结构（`bus_suspended` 分支在 D 链上优先级最高）的副产品。撤销请求后 DUT 走正常中止路径回

反向的一条（收尾段）：未挂起时把 `sie_wkup` 单独拉高 6 拍，驱动器仍关。
这是防 SIE 接错线的结构性保护（§2.11 真值表第 1 行），同样不是功能要求。

回归门（段 5）：撤挂起后立刻发一个 4 字节包，回环正常收到，末帧 4 字节，
确认旁路没把包路径的接线碰坏。

## 5. 仿真发现的 RTL 缺陷

> **本节是历史记录，读之前先看这条说明**：§5.1~§5.3 的两个缺陷属于**上一代 RTL**
> （4 态 FSM + `nrzi_lv`/`stuff_pend`/`stuff_after`/`byte_sent`/`data_end` 那套寄存器）。
> 2026-09-20 换 `_sy` 6 态设计后，这些寄存器**一个都不存在了**，缺陷本身也随之消失。
> 保留本节的理由有两条：① 它是**反向验证**的证据链（同一套 TB、19 个用例、缺陷编译回去
> 立刻 FAIL），证明这套用例**确有判别力**，不是"编什么都能过"；② 它记录了这块形状空间
> （跨字节边界 + 字节末位 + 连续多字节填充）为什么危险，新设计在这里踩的坑也就这两个。
>
> **新设计为什么天然避开这两个坑**（对应关系见各小节末的"新设计对应"）：
> 缺陷 1 = NRZI 状态漏更新 → 新设计**没有 NRZI 状态寄存器**，翻转基准直接就是输出寄存器
> `tx_bit` 自身，插 0 拍由 `tx_bit_nxt = ~tx_bit` 显式给出；缺陷 2 = 用饱和的 `bit_cnt`
> 分辨"字节收尾" → 新设计改用 `bit_cnt_7 && ~bit_stuff` 作载入条件，且把"末字节"提升成
> **独立状态** `S_DATA_LAST`，不再靠寄存器记账。

仿真是**先跑起来才暴露**这两个缺陷的：上一代定稿 RTL 初版 18 个用例里 **15 个 FAIL**，
且全部在**字节下标 1** 附近出错。两个缺陷根因不同、修法不同，但都落在同一个形状空间。

### 5.1 缺陷 1：插 0 拍 `nrzi_lv` 漏更新

**因**：`nrzi_lv`（NRZI 编码器的"当前线电平"状态）原本只在 `shift_en` 时更新。
**变**：而插填充 0 的那一拍是 **hold 拍**——`shift_en`=0（不移位），但那个填充 0 **照样要上线**。
于是这一拍 `nrzi_lv` 没被更新，下一拍拿它当翻转基准时用的是**更早一位**的电平。
**果**：从这个填充 0 之后，整段位序全错（NRZI 是就地递推，错一位后面全错）。

实测证据（`tx_pid_carry` 的 `E1_07`，缺陷编译回去跑）：

```
FAIL[E1_07]: 第 20 位不符 (实际 1, 期望 0)
  位流 @8: 实际 10000111111010000
  位流 @8: 期望 10000111111000000
  发出字节: e1 07
FAIL[E1_07]: 回环第 1 字节不符 (收到 0f, 发出 07)
```

**修正**：更新条件从 `shift_en` 改成"**本拍线上确实发了位**"，即 `S_SYNC`/`S_DATA` 全段
（插 0 拍也算）；`S_IDLE` 与中止复位到 J；`S_EOP` 整段不更新（SE0 两拍旁路、J 拍由 `tx_bit` 强制）。

**新设计对应**：`nrzi_lv` 这个"当前线电平"寄存器已经被**删掉**——`tx_bit` 自己就是那个
寄存器，`tx_bit_nxt` 里 `bit_stuff ? ~tx_bit : (data_shift[0] ? tx_bit : ~tx_bit)` 一句把
"插 0 拍也要翻转"写死在表达式里，不存在"某拍忘了更新"的入口。这一改写由 §4.2 的逐拍表核实。

### 5.2 缺陷 2：`data_end` 把中途插 0 误判成字节收尾

**因**：字节收尾条件 `data_end` 原本写的是 `(bit_cnt == 3'd7) && (stuff_pend || !stuff_after)`。
**变**：`bit_cnt` 到 7 后**饱和**，它分不清"b7 本拍刚发出"和"b7 还没发、只是中途插 0 时
`bit_cnt` 已经爬到 7"——两者都会看到 `bit_cnt==7`。中途插 0 被误判成收尾。
**果**：该字节的 `b7` 随下一次载入被冲掉，**整字节丢 1 位**（位流短 1~8 位，取决于有几个中途插 0）。

实测证据（缺陷编译回去跑）：

```
FAIL[dense_FE]: 位流长度 48, 期望 50          (tx_stuff_dense)
FAIL[pos_multi]: 位流长度 96, 期望 104        (tx_stuff_pos_scan, 8 个填充全丢)
FAIL[long_64B]: 位流长度 548, 期望 549        (tx_long_loopback)
FAIL[sweep]: 位流长度 24, 期望 25             (tx_byte_sweep, 首个出错字节 0x7e)
```

**修正**：新增一个 `byte_sent` 寄存器（本字节 b7 是否已上线），把 `data_end` 的两个来源分开：

```verilog
wire b7_now   = shift_en && (bit_cnt == 3'd7);
wire data_end = (st_state == S_DATA) &&
                ((b7_now && !stuff_after) ||     // ① b7 后无需插 0
                 (stuff_pend && byte_sent));     // ② b7 那拍凑满 6 连 1 → 补发的 0 才收尾
```

中途插 0（b7 未发）两条都不成立 → 不收尾，继续把 b7 发完。

**新设计对应**：`byte_sent` / `data_end` 也都删了。载入条件写成
`data_load_en = (S_SYNC || S_DATA) && bit_cnt_7 && ~bit_stuff`——中途插 0 那拍 `bit_stuff`=1，
天然把"载入"和"字节还没发完"分开，不需要额外寄存器记账。末字节另立一态
`S_DATA_LAST`，出口条件 `bit_cnt_7 && ~bit_stuff` 同样不受中途插 0 干扰。

### 5.4 `tx_en`：唯一走规则 6「兜底」路径的输出（2026-09-20 定稿）

这一条**不是缺陷**，是 `tx_en` 在规则 6 里的归类问题——它**不可能**靠现态译码寄存，
只能走"兜底"那条路，代价必须写明。

**因**：`tx_en` 要跟随 `tx_active`（SIE 的请求），而**组合逻辑的 D 端无法预知输入下一拍掉不掉**。
现态译码的全部前提（D 只由当前状态 + 当前寄存器值译出）在这里失效：无论怎么写，
"外部随时撤请求"这件事都晚一拍。

**变**：方案是**带进入/退出条件的寄存器**（`code_rtl.md` 规则 6 兜底第 ② 条）：

```verilog
always @(posedge clk12m or negedge ref_rstn) begin
    if (!ref_rstn)                  tx_en <= 1'b0;
    else if (tx_active_pos)         tx_en <= 1'b1;    // 起包: 上升沿 (进入边必晚一拍)
    else if (tx_stat_cur == S_IDLE) tx_en <= 1'b0;    // 收尾/中止: 模块自己的收尾条件
    else                            tx_en <= tx_en;
end
```

- **进入边晚一拍**（起包那拍 `tx_en` 还是 0）：无影响——那一拍线上仍是 J，不存在驱动器抢线。
- **退出边分两种**：模块**自己知道**的收尾（EOP）由 `st == S_IDLE` 钉住，落在 `tx_done`
  后一拍，与 2 拍 SE0 严丝合缝（§4.4 实测）；**外部撤销**（中止）钉不住。

**果**：中止路径上 `tx_en` 比 `tx_active`↓ 晚 **2 拍**才掉，期间多驱动 2 位数据位
（§4.7 的因果链实测：1927145 → 2093817 ps = 166672 ps）。这是本设计**唯一**的时序代价，
已被接受并明确记账：USB 不允许包中间停，中止本身就是错误路径；`tx_abort` /
`tx_abort_phases` 的判据已按此语义写（§4.7）。

**与 2026-09-17 那次尝试的差别**：当时 `tx_en` 的 D 写成 `tx_active & ~tx_done_now`
（只想钉住自己那次释放），在本设计里被"进入边靠 `tx_active_pos`、退出边靠 `S_IDLE`"取代。
另外那轮加的断言 `tx_en === tx_active`（直通契约）**已删除**——新设计的 `tx_en` 是寄存器，
契约本身不成立，留着只会误报。

> 这条的价值在于：规则 6 的"兜底"不是可有可无的附录。**"输出一律寄存器化"不是无条件
> 正确的**——判据是这条路径上输入的未来值能不能被本模块预知。能（EOP 收尾）就钉死；
> 不能（外部随时撤请求）就得认下那一拍偏移，并把它写进报告和用例判据。

### 6.1 建 TB 时发现的一个测试平台陷阱（非 RTL 缺陷）

本 TB 第一个 `clk12s` 上升沿出现在 **t=240ns**，而 `ref_rstn` 在 **t=200ns** 就抬高了 ——
所以 `always @(posedge clk12s ...)` 里所有 `if (!ref_rstn)` 分支**一次都不会执行**，

（见 `tb_tx_serial.v` 因果链记录器注释）。这条已写进注释，避免后面加信号时重踩。

### 8.2 复跑方法

> **注意**：`--annotate` 出来的文件比源文件**多 1 行头**（`// verilator_coverage annotation`），
> 行号换算要**减 1**。且 `cov/ann*` 是手工生成的目录，`make cov` **不会**重建它们——
> 判读前先确认手上那份 annotate 与当前 RTL 同步（最省事的办法是重跑一次 `--annotate`）。

`make cov` 先用 iverilog 那份同一套 TB 的功能判据卡一遍：**任用例非 `TEST PASSED` 即中止**，不会拿一次跑挂的激励去出覆盖率数字。

### 8.3 工具与口径（三点必须说明，否则数字会被误读）

1. **为什么是 Verilator**：iverilog 无覆盖率能力。两仿真器跑同一份 TB（VCD 路径已做逐字节等价性双证），**功能判据仍以 iverilog 回归为准**，Verilator 只负责出数字。
2. **必须跨用例合并**：单用例只走自己那条路径（如 `tx_pid_only` 走不到位填充，`tx_susp_wkup` 之前的 19 个用例里 `bus_suspended` 恒为 0）。合并用 `verilator_coverage --write`。本节的百分比全部是 **20 用例合并后**的口径。
3. **FSM 那一维是自建的**：Verilator 的 `--coverage-fsm` **认不出本 DUT 的 FSM**——它只识别单段式写法（状态变量在组合块里直接 `case` 赋值），而本模块是 `code_rtl.md` 要求的两段式（组合算 `tx_stat_nxt` + 时序搬 `tx_stat_cur`），且 `case` 外还套了 `if (~tx_active)` 优先分支 → 检测器放弃，`merged.dat` 里 **0 条 fsm 记录**（`fsm_state/fsm_arc` 恒为 0/0）。与其为工具改已验收的 RTL，不如在 TB 侧分层引用 `u_tx.tx_stat_cur` 自己数（`print_fsm_coverage`），再用 `tools/merge_fsm_cov.py` 跨用例相加（该脚本已按 6 态配置：`states` 映射与 **16 条合法弧**的 `legal` 集合，见 `merge_fsm_cov.py` 的 tx profile）。

**合并后的 FSM 迁移矩阵**（拍数，20 用例相加）：

|---|---:|---:|---:|---:|---:|---:|
| IDLE | 11994 | 1352 | 0 | 0 | 0 | 0 |

> 用例 20 只多了 `IDLE` 里的几十拍（挂起 40 + 唤醒 120 + 回归段）与一次完整的包往返，
> 上表比 19 用例版各格涨的那一点就是它。**`bus_suspended` 恒 1 期间 FSM 停在 `S_IDLE`
> 是设计意图**（§2.11 旁路不占状态），矩阵里没有新弧印证了这一点。
**16 条合法弧全中，且无任何设计意图之外的迁移**——矩阵里每个非零格都能对上一条合法弧。

> 最初是 **0**：不是不可达，是激励缺口（前面四个中止相位都够不着），于是补了
> `tx_abort_phases` 的相位 5/6（§4.7）。补完之后这两条各走了 1 拍——**恰好 1 拍，因为每个

> 另几个"小数字"格同理可解释：`SYNC→IDLE`(2) / `DATA→IDLE`(3) / `EOP1→EOP1`(27 拍) 分别
> 来自中止路径与尾填充自环。

### 8.4 未覆盖项的定性：只剩一条 `case` 兜底

`_sy` 设计复跑后，DUT 未覆盖项**只剩 1 条**（行号按 2026-09-22 加旁路后的 RTL，`--annotate` 定位）：

| 位置 | 语句 | 未覆盖维度 | 为什么结构不可达 |
|---|---|---|---|
| `usb_tx_serial.v:161-162` | `default: begin tx_stat_nxt[2:0] = S_IDLE; end` | 行 | `tx_stat_cur` 是 3 bit，6 个取值已全部在 `case` 里枚举，剩下的 `3'd6`/`3'd7` 无路可进 |

> 旁路分支**不是**未覆盖项：`bus_suspended` 的"1"侧由用例 20 走、"0"侧由此前 19 个用例走，
> `sie_wkup` 在 `bus_suspended=1` 下同样两侧都走到了（段 2 起 1、段 3 落 0）。
> 这也是表达式/翻转两个维度的分母各涨 2/4 的原因。

这条是 `code_rtl.md`「if-else 补全 + `case` 配 `default`」强制要求的兜底分支，**必须留在 RTL 里**，
属正常豁免而非设计缺口。

> **比上一轮少了一条**：2026-09-17 那版还有一条 `ones_cnt_nxt` 的保持臂（条件是
> `S_DATA && !stuff_pend && !shift_en`，而 `shift_en` 的定义使该条件自相矛盾）。新设计把
> 那个计数器换成 `bit_ones_cnt`，"保持"一节合并进了 `_nxt` 三目线，那条矛盾分支随之消失。
> 也就是说：**这轮行点的分母变小（22 条）不是因为删代码，而是因为组合逻辑合并**，而
> **未覆盖项从 2 条减到 1 条是真实的结构简化**。

### 8.6 覆盖率反过来抓到的一个真问题（TB 复位序列缺陷）

首轮合并覆盖率显示 DUT 的 **10 条行、9 条表达式、1 条分支全部指向同一个根因**：所有 `always @(posedge clk12m or negedge ref_rstn)` 里的 `if (!ref_rstn)` 复位分支**一次都没执行**，`ref_rstn` 的 `1→0` 翻转也未覆盖。

根因在 TB：`clk12m` 由本 TB 的 `ref_clk` 四分频器 `div_cnt` 产生，而 **`div_cnt` 自己就被 `ref_rstn` 复位** → 复位期间 `clk12s` 恒 0，**复位窗口内一个 `clk12m` 沿都没有**，按住复位等多久都等不到。原先的 `#200; ref_rstn = 1'b1;` 正是踩了这个坑。改为「放开复位 → 等 `clk12s` 起振 → 再拉低制造 `negedge` → 正式撤复位」后，DUT 覆盖率从

| 维度 | 修前 | 修后 |
|---|---|---|
| 行 | 81.5% (44/54) | **96.3% (52/54)** |
| 分支 | 96.7% (29/30) | **100% (30/30)** |
| 表达式 | 87.7% (64/73) | **100% (73/73)** |
| 翻转 | 99.0% (97/98) | **100% (98/98)** |

危害不止是覆盖率不好看：**复位分支不执行 = 寄存器初值全靠仿真器默认值**，而 iverilog 是 `x`、Verilator 是 `0`，两家行为会漂移（`x` 参与比较恒假，会悄悄放过错误）。这个缺陷是覆盖率逼出来的，功能回归在修前修后都是 19/19 PASS——**只看 PASS 永远发现不了**。

> 本节表格里的 54/30/73/98 是**最早那版 RTL** 的行/分支/表达式/翻转点口径；后续两次换设计
> 都重新划了桶位（2026-09-17 → 19/106/108/160，2026-09-20 → 22/56/122/70，见 §8.1），
> **"复位分支必须被执行"这条结论三次都成立**——新设计的每个寄存器（含 5 个输出寄存器）
> 与每根 `_nxt` 线的复位分支均已覆盖。
