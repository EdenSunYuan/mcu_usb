## 1. 章节定位与整体结构

第 7 章定义 USB 的**物理/电气层**：信号电平、编码、时序、电源分配、连接器电气特性。它不涉及包格式（第 8 章）与设备框架（第 9 章），是 PHY 与模拟前端（以及我们的 CDR/反序列化）设计的直接依据。

三个小节：

| 小节 | 内容 | 对本项目的意义 |
|------|------|----------------|
| 7.1 Signaling | 驱动特性、信号电平、J/K/SE0/Idle、NRZI、位填充、SYNC、EOP、速率/帧/抖动 | **CDR、`usb_rx_deserial`、SIE 的全部数字判据来源** |
| 7.2 Power Distribution | unit load、电源/挂起电流、电压降预算、动态插拔 | 对纯数字 RTL 影响小，记录关键阈值即可 |
| 7.3 Physical Layer | 电气特性表（DC/AC/时序）、hub 时序、事件时序、波形 | 查表用，第 13 节汇总 |

## 3. 信号电平与总线状态（Table 7-1）

USB 半双工差分传输，逻辑状态如下（**FS 与 LS 的 J/K 极性相反**）：

| 总线状态 | 源端驱动要求 | 接收端判定 | 本项目相关 |
|----------|--------------|------------|------------|
| **Differential "1"** | D+>VOH, D-<VOL | (D+)-(D-)≥200mV 且 D+≥VIH | 逻辑 1 |
| **Differential "0"** | D->VOH, D+<VOL | (D-)-(D+)>200mV 且 D-≥VIH | 逻辑 0 |
| **Single-ended 0 (SE0)** | D+ 与 D- 均 <VOL | D+、D- 均 <VIL | EOP / Reset 的核心 |
| **J 态**（FS） | = Diff "1" | = Diff "1" | 空闲高电平态 |
| **J 态**（LS） | = Diff "0" | = Diff "0" | 注意极性反转 |
| **K 态**（FS） | = Diff "0" | = Diff "0" | SOP/Resume 用 |
| **K 态**（LS） | = Diff "1" | = Diff "1" | |
| **Idle**（FS） | — | D+>VIHZ 且 D-<VIL | D+ 被上拉拉高 |
| **Idle**（LS） | — | D->VIHZ 且 D+<VIL | D- 被上拉拉高 |
| **SOP** | — | Idle → K 沿 | SYNC 第 1 bit |
| **EOP** | SE0 ≈2 bit 时间 + J 1 bit 时间 | SE0 ≥1 bit + J | §11 |
| **Reset** | D+/D- <VOL 持续 ≥10ms | D+/D- <VIL 持续 ≥2.5µs | §12 |
| **Connect** | — | Idle ≥2.5µs（hub 侧 ≥2ms 判定） | 速度识别 |
| **Disconnect** | — | SE0 ≥2.5µs | 下游端口 |

**要点（对设计）：**

1. **J/K 极性由设备类型决定**，不是总线本身。FS 设备连上后，整段（含 hub 到 host）都按 FS 信号约定收发，即使传的是低速数据也如此（§7.1.2.1）。我们 FS-only 设备，**固定 FS 极性**即可：J = D+高/D-低，K = D-高/D+低。
2. **Idle = J，Resume = K**（接收端逻辑等价，见 Table 7-1 下方说明）。
3. SE0（D+、D- 同时低）是 EOP 与 Reset 的唯一标志，没有第三种差分态。
4. `rxdp`/`rxdn` 单端透传的 `line_state = {rxdp, rxdn}`（我们 `usb_rx_deserial` 中 `line_state==2'b00` 判 SE0）——**对应表中 `Single-ended 0 (SE0)` 接收端判据 `D+、D- 均 < VIL`**。

## 4. 差分 vs 单端接收（§7.1.4）

- **差分接收器**：数据解码靠差分信号，灵敏度 VDI≥200mV（共模 0.8–2.5V 内）。
- **单端接收器**：每根线各一个，阈值介于 VIL(0.8V)–VIH(2.0V) 之间，建议加迟滞抗噪。
- **关键特例**：差分切换期间 D+、D- 可能**同时暂时低于 VIH**（看起来像 SE0）。这段时间必须被屏蔽，不能误判为 SE0：
  - FS：最长 **TFST = 14ns**
  - LS：最长 **TLST = 210ns**

> **对应到 `usb_rx_deserial`**：EOP/SE0 检测不能一见到 `line_state==00` 就判 SE0，而要**连续计数 ≥ SE0_MIN 拍**（现设 `SE0_MIN=4`，ref_clk 48MHz 下 4×20.83ns≈83ns）再结合 SE0→J 沿判 EOP。83ns > TFST(14ns)，天然把差分切换的瞬时 SE0 过滤掉，且 ≥ 接收端 EOP 最小 SE0 宽 82ns（见 §11）。

## 5. 数据编码：NRZI（§7.1.8）

- **规则**：`1` = 电平**不变**；`0` = 电平**翻转**。
- 一串 0 → NRZI 每个 bit 都翻转；一串 1 → 长时间无跳变（这正需要位填充来保证时钟恢复）。
- 图中的高电平代表 J 态。

> **对应 `usb_rx_deserial` 的 NRZI 解码**：`nrzi_bit = (usb_cdr_data == nrzi_prev) ? 1'b1 : 1'b0`——电平不变→1，跳变→0，与规范完全一致。`nrzi_prev` 复位初值为 `1'b1`（idle J）。

---

## 6. 位填充 Bit Stuffing（§7.1.9）

- **发送端**：NRZI 编码前，数据流每连续 6 个 `1` 之后插入一个 `0`，强制产生跳变，保证接收端**至少每 7 个 bit 时间有一次跳变**，维持数据/时钟锁定。
- **生效范围**：从 SYNC 开始贯穿整包。**SYNC 结尾的那个 `1` 计入连续 1 计数**。
- **无例外**：即便填充位落在 EOP 前最后一个 bit，也要插入。
- **接收端**：NRZI 解码后识别并丢弃填充位。若在包内任何位置看到**连续 7 个 1**，判**位填充违例**，该包应被忽略。
- **Dribble 特例（§7.1.9 末尾 + Fig 7-23）**：EOP 前最后一个数据 bit 可能被 hub 切换歪斜拉伸，造成 EOP 前最多 **6 个满 bit 时间无跳变**却并非真正需要填充。因此接收端必须接受「EOP 前至多 6 个满 bit 无跳变」的包。

> **对应 `usb_rx_deserial`**：
> - `STUFF_MAX_ONE = 6`：连续 6 个 1 后下一个 0 是填充位 → `stuff_discard`；若连续 6 个 1 后又是 1 → `stuff_violate`（`rx_error`）。
> - `ones_cnt` 从 **1** 起算（SYNC 尾 1 计入），与规范「SYNC 结尾的 1 计入」一致。
> - dribble：规范要求「容忍 EOP 前多 1 个 bit 无跳变」，我们的 EOP 检测独立于位流水线（§11），靠 `SE0_MIN` 判定，天然不会因为 EOP 前少一个填充位而误判——**但需在 SIE 层校验 CRC 时兜底**（dribble 位不参与 CRC 校验是第 8 章的内容，此处只记录物理层要求）。

## 7. SYNC 同步头（§7.1.10）

- 每个包前缀的 NRZI 同步序列 = **数据 7 个 `0` 后接 1 个 `1`**，即数据字节 **80H**（0x80，LSb 先发）。
- 作用：让接收端 CDR 锁相、对齐位边界。

> **对应 `usb_rx_deserial`**：
> - SYNC 检测状态机找「≥`SYNC_MIN_ZERO`(=4) 个 0 + 1」，容忍 CDR 相位对齐吃掉的 SYNC 开头 1–2 个 0（§7.1.14 也提示「SOP 后第一个 SYNC bit 不该用于同步」——hub 会歪斜 SOP 首 bit，±5ns）。
> - SYNC 命中后 `ones_cnt<=1`（SYNC 尾 1 计入连续 1 计数），与 §6 一致。

## 8. 数据速率与时钟容差（§7.1.11）

| 速率 | 标称 | 容差 | 备注 |
|------|------|------|------|
| **Full-speed** | 12.000Mb/s | **±0.25% (2500ppm)** | host/hub/FS 设备统一 |
| Full-speed host 时钟 | — | ±0.05% (500ppm) | host 单独更严 |
| Low-speed | 1.50Mb/s | ±1.5% (15000ppm) | 允许低成本谐振器 |

容差包含：初始频率精度、晶体容性负载、供电电压、温度、老化等所有来源。

> **对设计的意义（关键）**：FS 设备侧位时钟允许 ±2500ppm，意味着两个端点间**最坏频率差可达 ±5000ppm**（host 在 +2500、device 在 -2500 之类）。接收端 CDR 必须能跟踪这个频率差。我们用 **48MHz ref_clk 对 12MHz 位时钟做 4× 过采样 + 自研 DPLL**，正是为了在「位时钟 ±0.25% + 源/宿频率差 + 抖动」下稳健恢复位采样点。第 10 节抖动的「4× 过采样 DPLL 可满足」是官方明确背书。

## 9. 帧间隔（§7.1.12）

- 帧间隔 **1.000ms ±500ns**，从一帧 SOF 的某点到下一帧 SOF 的同一点测量。
- host 可调帧间隔：默认 12000 bit/帧；另有 **±15 FS bit time** 的调整量用于同步外部时基；正常运行中软件每 6 帧最多调整 1 个 FS bit time。
- 不调整时连续帧间隔差 <0.5 bit time（TRFI）；调整时 <1.5 bit time（TRFIADJ）。
- hub 及部分 FS 设备需跟踪帧间隔并补偿自身频率容差。

> **对设计**：FS 设备必须能识别 SOF 并据此跟踪帧/挂起；我们的 SIE 只需识别 SOF 的 PID 即可，无需精确锁帧相位。帧间隔 ±500ns 与挂起（§12）判定无关——挂起只看「idle 时长」。

## 10. 源端抖动与接收端抖动预算（§7.1.13.1 / §7.1.15）

### 10.1 源端（数据发送方）抖动

| | 连续跳变 (consecutive) | 成对跳变 (paired) |
|---|---|---|
| FS | **±2.0ns** | **±1.0ns** |
| LS | ±25ns | ±10ns |

- 测量在数据线交叉点，负载同最大上升/下降时间。
- 抖动包含：差分缓冲延时、上升/下降失配、内部时钟抖动、噪声等。

### 10.2 接收端抖动预算（Table 7-2，FS）

| 抖动来源 | Next (ns) | Paired (ns) |
|----------|-----------|-------------|
| 源驱动抖动 | 2.0 | 1.0 |
| 源频率容差（最坏） | 1.5 (0.21/bit) | 3.0 |
| **源抖动合计** | 3.5 | 4.0 |
| Hub 抖动 | 15.0 | 5.0 |
| **抖动规范 (Jitter Spec)** | **18.5** | **9.0** |
| 目的频率容差 | 1.5 | 3.0 |
| **接收抖动预算 (Receiver Budget)** | **20.0** | **12.0** |

> Table 7-6 里的接收端要求即 `TJR1 = ±18.5ns`（next）、`TJR2 = ±9ns`（paired）。

### 10.3 对接收端的设计要求（关键）

规范原文明确：

> 接收端必须能在**名义（居中）数据沿位置 ± 1/4 bit cell** 的窗口内解码差分跳变。
> **（一个简单的 4× 过采样状态机 DPLL 即可满足这一要求。）**

- 1/4 bit cell ≈ 83.3ns/4 ≈ **20.8ns**（FS），正好对应接收抖动预算的 18.5–20ns 量级。
- 也就是说，**接收端能容忍数据沿在 ±20ns 量级内漂移**。

> **对本项目是决定性的背书**：我们的 CDR 方案正是 **48MHz 4× 过采样 + DPLL**，官方规范直接指出这种实现满足接收抖动要求。4× 过采样的量化步长 = 1 bit time / 4 ≈ 20.8ns，与 ±18.5ns 的接收预算量级吻合，采样点取「8 拍中的第 3~4 拍」能稳落位中心。

## 11. EOP / SE0 宽度（§7.1.13.2）

| | 发送端 SE0 宽 | 接收端最小接受 SE0 宽 |
|---|---|---|
| FS | **160–175ns**（TFEOPT） | **≥82ns**（TFEOPR） |
| LS | 1.25–1.50µs | ≥670ns |

- EOP 定义（§7.1.7.2 / Table 7-1）：驱动 D+/D- 到 **SE0 约 2 bit 时间**，随后**驱动到 J 态 1 bit 时间**，然后两端输出缓冲置高阻，总线被端接电阻拉回 Idle。**SE0→J 沿就是接收端判定的包结束点**。
- **接收端注意**：单端阈值 ≠ 差分交叉点，且 SE0 跳变相对 NRZI 时钟**异步**，接收端 EOP 检测不能依赖位时钟，要独立于数据流水线。
- hub 见 SE0 ≥ TFST 后回 J 即可 tear down connectivity（对任何有效 EOP 必须 tear down）。

> **对应 `usb_rx_deserial`**：
> - EOP 检测**独立于 bit 流水线**，在 ref_clk 域监测 `line_state`：SE0 计数（`se0_cnt`）→ SE0→J 沿（`line_state==2'b10` 且 `se0_cnt≥SE0_MIN`）判 `eop_det`；SE0→K（`2'b01`）判 `eop_err`。
> - `SE0_MIN=4`（≈83ns）**介于接收端最小 82ns 与发送端 160ns 之间**，既接受被 hub 截短的 EOP，又不把差分切换的瞬时 SE0（≤14ns，§4）误判。这是规范数字直接落地的体现。
> - 发送端（TX）EOP 由 SIE 生成，需产生 160–175ns 的 SE0（约 2 个 bit time），由 clk_mux/PHY 时序保证。

## 12. 总线事件时序（Connect / Disconnect / Reset / Suspend / Resume）

### 12.1 Connect / Disconnect（§7.1.7.1）

- 无设备时，host/hub 下拉电阻把 D+、D- 都拉低 → SE0。
- **Disconnect**：host/hub 未驱动数据线时，下游端口 SE0 持续 **>2.5µs** 判断开。
- **Connect**：hub 检测到某根数据线被拉到 VIH 之上 **>2.5µs** 判连接（FS 看 D+ 拉高，LS 看 D- 拉高）。
- 速度识别：reset 前采样总线态，或 reset 后浮空总线 2.5µs 后评估（Diff 1=FS，Diff 0=LS，SE0=未连接）。
- 上电时序（Fig 7-19）关键项：
  - t2 = **TSIGATT ≤ 100ms**：VBUS 达 4.01V 到设备 D+/D- 达 VIH(min)（发 attach）的时限。
  - t3 = **TATTDB ≥ 100ms**：系统软件的防抖间隔。

> **设备侧也能在 D+/D- 上做插拔检测（规范未强制，但真实存在，自供电设备尤甚）**
>
> 注意：上面 TDCNN/TDDIS（数据线 connect/disconnect）是规范**强制在 host/hub 下游口**的；但**纯 device 也常在数据线上做"插入/拔出"检测**，做成中断标志位。原理是检测 host/hub 下游口那对 **15kΩ 下拉电阻是否在场**：
>
> | FS 设备状态（自供电，仍带电） | D+（自己 1.5kΩ 上拉） | D-（无自己上拉） | 判据 |
> |---|---|---|---|
> | 已插入（idle） | 约 3.0V（被下拉分压） | **0V（被 15kΩ 下拉）** | D- 低 = 有下拉 |
> | 已拔出 | 3.3V（仅自己上拉） | **浮空** | D- 浮空 = 无下拉 |
>
> 最干净的观察线是**与自己上拉相反的那根**（FS 看 D-，LS 看 D+）。这跟 host/hub 的 TDCNN/TDDIS 判据不同，但物理来源同是那对下拉电阻。是否实现取决于供电类型：总线供电设备用 VBUS 检测即可；自供电设备需补这条数据线检测。

### 12.2 Reset（§7.1.7.3）

- hub 通过驱动**长 SE0** 发 reset；结束后设备进入 Default 态（§9.1）。
- **hub 驱动 reset 时长 TDRST = 10ms（min）**；root hub 名义 **50ms（TDRSTR）**；若分多段，段间隔 <3ms（TRHRSI）。
- **设备侧判据**：上游端口见 SE0 **>2.5µs（TDETRST）** 即可视为 reset；reset 须在信号结束前生效。
- reset 恢复时间 **TRSTRCY = 10ms**：reset 移除后设备须能在 10ms 内接受 `SetAddress()`。

> **对应设计**：设备端 Reset 检测 = 长时间 SE0（>2.5µs）判定，而非精确测 10ms。我们的 PHY/系统层需一个「SE0 持续 >2.5µs」的检测器触发复位状态机。**Reset 必须能把设备从 Suspend 唤醒**。

### 12.3 Suspend（§7.1.7.4）

- 所有设备必须支持挂起。设备见上游总线**连续 Idle >3.0ms** 开始进入挂起；所有端口总线空闲 **10ms** 内必须真正挂起、只抽挂起电流。
- SOF 每帧一次，防止 FS 设备挂起（无 SOF 即可能挂起）；LS 设备靠 keep-alive（=LS 的 EOP）。
- 挂起期间仍须维持 D+/D- 上拉电阻供电，保持 Idle 供 hub 维持连接状态。
- Global Suspend：host 停止一切发送（含 SOF）；Selective Suspend：`SetPortFeature(PORT_SUSPEND)`。

### 12.4 Resume（§7.1.7.5）

- 设备挂起中，上游收到**任何非 idle 信号**即恢复。
- **host 发 resume**：至少 **20ms（TDRSMDN）**，末尾用标准 LS EOP 结束；恢复后 3ms 内须开始发 SOF。
- **设备远程唤醒**：须总线已连续 idle **5ms（TWTRSM）** 才能发起；resume 信号保持 **1–15ms（TDRSMUP）**；结束时设备置高阻（不驱动到 J）。
- hub 收到 resume 后 **100µs（TURSM）** 内向上游及使能下游转发。
- 恢复恢复时间 **TRSMRCY = 10ms**（软件不访问受影响段）。

> **对应设计**：远程唤醒的三个前置条件（挂起、特性使能、K 1–15ms 后交高阻）见
> `doc/design_rpt/bus_state_design.md` §2.7 末。硬件侧 `usb_bus_state` 只出 `suspended`
> （idle >3ms，比规范的 5ms 早，余下 2ms 由软件等）；「idle ≥5ms」的计时与「特性是否使能」
> 都在软件/寄存器层，SIE 不另做检测。resume 波形 = 持续 K 态（Table 7-1 中 Resume=K）
> 1–15ms，由 `usb_tx_serial` 的唤醒旁路产生（`usb_bus_state` 的 `bus_suspended=1`
> 且 SIE 的 `sie_wkup=1` 时直驱 K，不占状态机；见 `tx_serial_design.md` §2.11）。

## 13. 电源分配要点（§7.2，摘记）

- **unit load = 100mA**。设备要么 **low-power（1 unit load）** 要么 **high-power（≤5 unit loads）**；**所有设备上电默认 low-power**，升到 high-power 由软件控制。
- 设备上游口**只能 sink 电流，绝不 source**；VBUS 无电时不得给上拉电阻供电。
- **挂起电流**：low-power 设备 / high-power 设备处于 low-power 态 → **≤500µA**；配置为 high-power 且使能远程唤醒 → 可达 **2.5mA**。
- VBUS 电压：high-power 端口 4.75–5.25V；low-power 端口 4.40–5.25V。
- 浪涌电流限制：动态插拔时 hub VBUS 最大跌落 330mV；设备端负载上限 10µF ∥ 44Ω；hub 端口旁路 ≥120µF。
- 动态 detach：1m 电缆最大 60MHz 的 flyback 噪声；设备端建议 ≥1.0µF VBUS 旁路。

> **对纯数字 RTL 项目**：本节基本不进入 RTL。唯一相关的是——挂起电流阈值（500µA/2.5mA）是**板级/模拟**约束，提示 PHY 在挂起态要关闭大部分偏置。设备控制器本身无需处理电源切换。
