# USB 1.1 Full-Speed Device RTL 设计参考手册-------挂起和唤醒

> 基于 USB 1.1 规范及 ST / GigaDevice / Renesas 等大厂 SIE 实现反推总结
> 适用：纯 RTL 自研 USB 1.1 FS Device IP

***

## 1. 挂起 (Suspend) 设计

### 1.1 挂起检测

| **参数** | **数值**       | **说明**                  |
| ------ | ------------ | ----------------------- |
| 检测阈值   | **>3 ms**    | 总线处于 J 状态（Idle）持续超过 3ms |
| 挂起电流   | **≤ 500 µA** | 挂起后从 VBUS 汲取电流上限        |
| 上拉电阻   | **必须保持**     | 不能断开，否则主机会认为设备已拔除       |
| 状态保持   | 保持           | 地址、配置、端点状态不能丢失          |

### 1.2 挂起状态信号设计

```
┌─────────────────────────────────────────────────────────┐
│  SIE 内部信号（CPU 不可直接访问）                           │
│  • suspended：总线空闲 >3ms 时硬件自动置位                  │
│  • 清 0 条件：总线出现任何非空闲活动（K、SE0、Token等）        │
│                                                         │
│  注意：suspended 清 0 ≠ SIE 退出挂起处理模式                 │
│       远程唤醒期间设备自己驱动 K 态，suspended 会变 0         │
│       但 SIE 协议层状态机仍保持挂起，直到主机 Resume          │
└─────────────────────────────────────────────────────────┘
```

### 1.3 挂起中断标志 (SUSP\_INT)

* **属性**：W1C（Write-1-to-Clear）
* **触发方式**：**边沿触发**（suspended 上升沿 0→1 时置位一次）
* **关键设计**：
  * 必须是边沿触发，不能是电平触发，否则 ISR 返回后会重复触发死循环
  * 清除后，只要总线持续空闲，不会再次置位
  * 设置 `FSUSP=1` 后，挂起检测被禁用，进一步防止重复中断

### 1.4 CPU 可见寄存器

| **寄存器位**      | **属性** | **功能**                                     |
| ------------- | ------ | ------------------------------------------ |
| `ISTR.SUSP`   | W1C    | 挂起中断标志，3ms 时硬件置位                           |
| `CNTR.FSUSP`  | RW     | **强制挂起控制**。CPU 写 1 → SIE 进入挂起处理模式；写 0 → 退出 |
| `CNTR.LPMODE` | RW     | **低功耗模式控制**。CPU 写 1 → PHY/时钟进入低功耗；写 0 → 恢复 |

**ISR 流程（进入挂起）：**

```
SUSP 中断触发
  → CPU 读 ISTR，确认 SUSP=1
  → 写 ISTR = CLR_SUSP（W1C 清中断标志）
  → 写 CNTR.FSUSP = 1（通知 SIE 进入挂起处理）
  → 写 CNTR.LPMODE = 1（PHY 低功耗）
  → 系统进入低功耗模式（WFI/STOP）
```

## 2. 远程唤醒 (Remote Wakeup) 设计

### 2.1 前提条件（必须同时满足）

1. **设备处于挂起状态**（suspended=1）
2. **总线已连续空闲 ≥5 ms**（TWTRSM 参数）
3. **能力声明**：配置描述符 `bmAttributes` bit 5 = 1
4. **主机使能**：主机通过 `SetFeature(REMOTE_WAKEUP)` 显式使能

### 2.2 关键时序参数

| **参数**    | **数值**               | **说明**               |
| --------- | -------------------- | -------------------- |
| 进入挂起      | **>3 ms** 空闲         | 设备必须等满 3ms 才认为挂起     |
| 允许远程唤醒    | **≥5 ms** 空闲         | 规范要求，不是厂商自行规定        |
| K 态驱动时长   | **1 \~ 15 ms**       | 设备驱动 K 态的窗口          |
| 推荐时长      | **10 ms**            | 业界共识，兼容性最佳           |
| 主机接管时限    | **检测到 K 后 1ms 内**    | 主机必须开始发送完整 Resume 序列 |
| 主机 Resume | **≥20 ms** K 态 + EOP | 主机接管后的 Resume 序列     |

### 2.3 大厂范式：RESUME 位控制

**所有大厂（ST、TI、Silicon Labs 等）的统一设计：**

| **位**                  | **操作**      | **效果**                  |
| ---------------------- | ----------- | ----------------------- |
| `CNTR.RESUME` / `WKUP` | CPU 写 **1** | 硬件立即在总线上驱动 **K 状态**     |
| `CNTR.RESUME` / `WKUP` | CPU 写 **0** | 硬件立即停止驱动 K，总线回到 J（Idle） |

**特点：**

* 纯**电平控制**，无硬件自动超时
* 定时完全由**固件/CPU 控制**（通常利用 ESOF 中断 1ms 计数，延时 10ms 后清 0）
* **硬件不做 5ms TWTRSM 门控**，依赖固件从低功耗唤醒的自然延迟（通常 >2ms）

### 2.4 远程唤醒完整流程

```
[总线空闲开始]
    │
    │ 3ms
    ▼
[SUSPENDED=1] ──→ SUSP 中断 ──→ CPU 设置 FSUSP=1, LPMODE=1
    │                                 系统进入低功耗
    │
    │ [总线继续空闲，累计 >5ms]
    │
    │ 外部唤醒事件（按键/GPIO 等）
    ▼
[CPU 被中断唤醒]
    │
    │ 可选：查询 RWU_RDY（5ms 标志）
    ▼
[CPU 写 RESUME=1] ──→ 硬件驱动 K 态
    │
    │ 固件延时 10ms（ESOF 中断计数或定时器）
    ▼
[CPU 写 RESUME=0] ──→ 硬件释放总线，总线回到 J
    │
    │ ⚠️ 此时 FSUSP 仍为 1！SIE 仍保持挂起处理模式！
    │
    │ 等待主机接管 Resume
    ▼
[主机检测到设备 K 态]
    │
    │ 主机驱动 K 态 ≥20ms + EOP
    ▼
[SIE 检测到主机 Resume] ──→ 硬件自动：
    │                           • SUSPENDED 清 0
    │                           • 恢复 PHY/时钟
    │                           • 置位 ISTR.WKUP=1
    ▼
[WKUP 中断触发]
    │
    ▼
[CPU 执行 Resume ISR]：
    1. ISTR = CLR_WKUP（W1C 清中断标志）
    2. CNTR.LPMODE = 0（退出低功耗）
    3. CNTR.FSUSP = 0  ← ⚠️ 正式退出挂起处理模式
    4. 恢复系统时钟（SystemClock_Config）
    5. 恢复 USB 正常中断使能（CTRM 等）
```

### 2.5 关键设计要点

**1. SIE 在远程唤醒期间不退出挂起**

* 设备驱动 K 态时，SIE **不会**因为检测到 K 态（自己发的）而退出挂起
* 必须用 `drive_k` 信号做门控：`drive_k == 0` 时检测到的 K 态才认为是主机的 Resume
* 远程唤醒期间 `suspended` 内部信号会变 0（因为总线不是 J 状态），但 SIE 协议层状态机**忽略**这个变化

**2. FSUSP 清 0 时机**

* **绝对不要在 RESUME=0 时清 FSUSP**
* FSUSP 必须在 **WKUP 中断 ISR 中**清除
* RESUME=0 只是"我发完信号了"，不等于"挂起结束了"
* 提前清 FSUSP 会导致 SIE 提前退出挂起处理，可能错过后续主机 Resume 或重复进入挂起

**3. 5ms 门控建议**

* 大厂硬件**不做 5ms 门控**，依赖固件自然延迟
* **建议自研 IP 增加硬件门控**：提供 `RWU_RDY`（5ms）只读标志
* 或提供 `WKUP_REQ` 控制位，硬件内部缓存请求，自动延迟到 5ms 后才驱动 K 态

**4. 硬件看门狗保护**

* 大厂 RESUME 位无硬件自动超时，完全依赖固件在 15ms 内清 0
* **建议自研 IP 增加 15\~20ms 硬件看门狗**：固件卡死时自动强制释放总线，防止违规长期占用

## 3. 主机 Resume 设计

### 3.1 主机 Resume 序列

```
主机驱动 K 状态 ≥20ms
    │
    ▼
主机发送低速 EOP（SE0 持续 2 个低速 bit times，约 1.33 µs）
    │
    ▼
总线回到 J 状态（Idle）
    │
    ▼
主机立即开始正常传输（SOF / Token）
```

### 3.2 设备端检测

* 设备**不需要等满 20ms**。规范没有规定设备端检测 K 态的持续时长门槛
* 实际 RTL 中需要**消抖**：建议 **4\~8 bit times**（\~0.3\~0.7 µs）确认不是毛刺
* 检测到有效 Resume 后，硬件**自动**完成以下操作：
  * 退出挂起状态（SUSPENDED 清 0）
  * 恢复 PHY/时钟（如果 LPMODE 被设置）
  * 置位 `ISTR.WKUP` 中断标志
* CPU 在 ISR 中：清中断、清 LPMODE、清 FSUSP、恢复系统时钟

### 3.3 与 Reset 的区别

| **事件**     | **地址**    | **配置** | **端点状态** | **需要做什么** |
| ---------- | --------- | ------ | -------- | --------- |
| **Resume** | **保持**    | **保持** | **保持**   | 恢复时钟，继续工作 |
| **Reset**  | **清零为 0** | **清零** | 复位       | 重新枚举      |

**固件必须严格区分 Resume 和 Reset 中断，不能混为一谈。**

## 4. 寄存器设计建议

### 4.1 状态寄存器（RO，只读）

| **位** | **名称**     | **说明**                |
| ----- | ---------- | --------------------- |
| 1     | `K_ACTIVE` | 当前是否在驱动 K 态（调试/状态查询用） |

### 6.2 中断标志寄存器（W1C）

| **位** | **名称**      | **说明**           |
| ----- | ----------- | ---------------- |
| 0     | `SUSP_INT`  | 挂起中断标志，3ms 时硬件置位 |
| 1     | `WKUP_INT`  | Resume/唤醒中断标志    |
| 2     | `RESET_INT` | Bus Reset 中断标志   |

### 6.3 控制寄存器（RW）

| **位** | **名称**            | **说明**                      |
| ----- | ----------------- | --------------------------- |
| 0     | `FSUSP`           | 强制挂起。写 1 进入挂起处理，写 0 退出      |
| 1     | `RESUME` / `WKUP` | 远程唤醒控制。写 1 驱动 K 态，写 0 释放    |
| 2     | `RWU_EN`          | 远程唤醒使能（主机 SetFeature 后软件置位） |
